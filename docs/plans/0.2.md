# KnowCode 0.2 plan

October 20, 2026. Two to three weeks of work.

0.2 makes answers that agents use without re-checking them, and that cost less to carry. It publishes a
reproducible public evaluation as its gate. 0.1 shipped working answers. But an earlier private agent study found
no benefit: agents re-checked almost every answer with their own tools, and carrying the tool schemas cost more
than it saved. 0.2 is about removing those two costs, and showing it publicly, failures included.

## Gate

0.2 ships when the [public evaluation](../../eval/public-v1/method.md) has been run and published: its accuracy bank
and a pre-registered agent study, with every failure and loss reported. No comparative or benefit claim appears
anywhere before that.

**Pre-registered success criteria** (fixed before any 0.2 change is measured):

1. **Re-check rate at least halved.** That is the share of KnowCode answers the agent re-verifies with its own
   reads or searches before using them.
2. **Answer F1 at least equal** to the plain-tools arm.
3. **Fewer research tokens** per question than the plain-tools arm, schemas included.
4. **Unprompted use:** in sessions where KnowCode is available and the prompt doesn't mention it, the agent uses it
   for the questions it covers. 0.1.0's clean-machine runs give the starting point: zero calls before the 0.1.0 hook
   fix and the always-loaded tools, one call per question after.

A criterion that is missed is reported as missed. The release can still ship, with the miss stated plainly. What it
can't do is claim the benefit.

## Order

Measure before changing. Week 1 pre-registers the study and runs the baseline on the 0.1.1 code. Weeks 1–2 build
the changes. Week 3 re-runs the same study, publishes, and releases.

### 1. Pre-registration and baseline (week 1, first)

- **Freeze the study:** cohort commits, question sampling ([sampling](../../eval/public-v1/sampling.md)), labels and
  their review, arms (plain tools; KnowCode via MCP), model and client versions, metrics and the scoring script.
  Publish the frozen protocol in this repo before the baseline runs.
- **Measure re-checks:** detect them from transcripts (reads, searches or re-asks that cover what a KnowCode answer
  already stated), with the detector itself checked against hand labels.
- **Run the baseline** on 0.1.1 and keep the raw transcripts. These are the numbers 0.2 has to beat.

### 2. Answers agents don't need to re-check

The study traced re-checks to answers that left the agent unsure: no source to look at, no sign the index was
current, a walk that stopped early with no next step.

- **Cited source:** every symbol, edge and step in an answer carries the exact source lines it rests on (a bounded
  snippet, not just `file:line`). Agents read what they would otherwise open.
- **Verified at query time:** cited lines are re-read from the working tree when the answer is built and checked
  against the index. The answer says `verified` per citation, or names the drift, so "is this stale?" never needs a
  separate read.
- **Walks that finish:** multi-hop questions get one tool call that follows the chain itself (across calls, DI, HTTP,
  the bus and SQL) to a stated depth and budget. Every stop gives its reason and the exact continuation call, using the
  existing `kc_flow` / `kc_path` machinery. No silent early stops.
- **Measured by** the re-check rate and F1 in the study. Each item lands with tests on the answer contract.

### 3. Cheaper to carry

- **Smaller default answers:** tighter default caps and leaner fields. Detail comes through cursors (`kc_more`) and
  explicit options. Every cut still says what was left out.
- **Schema cost:** measure what a session actually loads, with tool search on and off, and with the four
  always-loaded tools. Then choose the default profile and always-loaded set by measurement. That choice might be
  making `core` the default, shortening descriptions, or changing the always-loaded set.
- **Measured by** research tokens per question, schemas included.

### 4. Adoption

0.1.0's clean-machine runs showed that agents ignore available tools unless something points them there. The Bash
hook and always-loaded tools fixed that for two questions.

- Keep the unprompted-use measurement in the clean-machine script and the study.
- Tune the server instructions and skill descriptions against it, keeping the words agents search with first.

### 5. Ride-alongs

- **`fetch-deps`** (CLI only, as decided in [decisions](0.1.0-decisions.md)): clone the repos a manifest depends on,
  into a directory the user names, so cross-repo answers can reach them. MCP never clones.
- **`history deepen`** (CLI only): deepen shallow clones so history-based answers (`hotspots`, `ownership`,
  `coupled`) have something to read. It reports how deep the history is now.

### 6. Tech debt

- **One per-query context object** for what's now collected per thread: gone-checkout notes and the `incomplete`
  entries for repos left out of a fan-out. It is passed through the query instead.
- **Facts out of the wrong table:** unsupported facts stored with infrastructure facts get their own place.
- **One graph abstraction** for the walks (`trace`, `path`, `flow`, `impact`), so the change in item 2 lands once.

## Not in 0.2

- Windows.
- Questions the bank shows KnowCode losing today (co-change and history lookups), beyond what item 5 enables.
- Paused feature targets.

## Release

- **Per pull request:** the usual gates and public CI.
- **Clean-machine acceptance:** the script on Linux and macOS, including unprompted sessions.
- **Updates:** a cross-version update from 0.1.x.
- **Evaluation:** the published evaluation (the gate) is linked from the README and the release notes.
