# KnowCode 0.5 plan

October 26, 2026. Two to three weeks of work.

0.5 makes KnowCode answer the questions grep can't, and follow code across the boundaries that hide it today: from a
method to its history, from an implementation into the repositories that depend on its library, and from a call into
an SDK to the server route it reaches. It also makes KnowCode's measurements cheap enough to run on every change.

What 0.4 left open:

- **History questions were never measured in public.** The public studies exported their repositories without
  history, so neither had a history question. Measured since on full clones, `coupled` ranks a file's partners mostly
  by how recently they changed, and its top partner for an Autofac core file was a tooling file shared through
  sweeps; a plain `git log --name-only | sort | uniq -c` matches "what usually changes with this" better. KnowCode has
  no history for a method at all, while plain git does badly there: `git log -L :name:file` finds no match for
  indented C# members, and `git log -S` names the wrong commits.
- **Impact stops at a library boundary.** It lists the first hop into repositories that depend on a library, then
  stops, so a caller of that caller in a dependent repository is missed.
- **Calls through an external SDK aren't linked.** About 400 calls in one public web client go through an SDK whose
  code isn't in the workspace; KnowCode says so, but links none. Of the untagged calls KnowCode does link by name, 14
  point at the wrong server action, marked `exact`.
- **Codex's session-start hook needs a manual trust step** that a re-install could undo, and KnowCode couldn't tell
  whether it was active.
- **The release gate runs by hand.** Every regression check takes a person to run it before a release.

## Gate

0.5 ships when these pass, compared with 0.4.0, and are published with the release (no model calls):

- **Tool cost per turn** for each profile, counted exactly: no growth beyond what the release notes name and justify.
- **Replay gate** on every published recorded call: no regression in precision, recall or answer bytes beyond its
  tolerance, and no call that errors (0.4.0 has 15 failing `kc_search` calls; they're fixed).
- **History questions:** a public set of 14 questions with labels taken from git alone (`eval/history-v1`), replayed
  like the recorded calls. KnowCode answers the method-level and caller questions at least as well as the plain-git
  answer they're labelled against; the two file co-change questions are controls.
- **Workspace gate, clean-machine acceptance and an update from 0.4.0.**

**Milestone study:** one run of public-v3's 24-question core tier in the full client (about $20), after the changes
land, to see whether 0.4's single tool and session-start line changed how agents use KnowCode. It's reported
descriptively; it doesn't gate the release.

No comparative or benefit claim about agents is made from the gate.

## Order

Each change measures its own before and after on the replay gate or a labelled public set before it merges. Weeks 1–2
build; week 3 runs the gate on the release candidate, the milestone study, publishes and releases.

### 1. Cheap, continuous evaluation

- **The replay gate on every pull request:** a subset of the five small public repositories, about six seconds a build,
  on Linux in CI, compared with the latest release; it fails on a regression and posts its table. The full replay runs
  before a release.
- **History questions in the gate:** `eval/history-v1` joins the replay, from full-history clones at pinned commits;
  locally if it's too heavy for CI.
- **Fix what the gate found:** the 15 `kc_search` calls that fail on 0.3.0 and 0.4.0 alike.
- **Flaky checks:** fix the checks that fail only under load (first-run timing races), so a red build means something.

### 2. Win where grep can't

- **History of a method:** a history op over the span KnowCode already knows: the commits that changed it, the first
  and last change and who made them, blame over its lines, and what else changed in those commits. Its cost is capped,
  and an answer says when it was cut.
- **`coupled` ranked by what usually changes together:** shared commits and confidence first, recency shown on its own,
  tooling sweeps kept out of the top. The file co-change controls show it now matches plain git.
- **History joined to the call graph:** which of a method's callers changed with it. No text search can answer this.
- **Reachable:** the history ops are named in the default tool's description and instructions, within their byte
  budget, so an agent doesn't need to ask for help to find them.

### 3. Reach across boundaries

- **Impact into dependent repositories:** a walk continues from a library's method into the repositories that depend
  on it. Calls resolved exactly are walked by default; calls through an interface with several implementations are
  listed and not walked past, with the call that continues. A per-answer budget bounds the cost, and the answer says
  when it was reached.
- **SDK calls linked through the SDK's own code:** for a package the repository itself declares as an external
  client, KnowCode reads the package's code from the checkout's `node_modules` when the installed version matches the
  lockfile, applies the repository's privacy file, and indexes it into the cache; nothing is written into the
  repository and nothing is fetched. A call then links through the package's method to the request it makes. This is
  a deliberate exception to reading tracked files only, and can be turned off.
- **Wrong exact links fixed:** an untagged call to an external client isn't linked `exact` by name when its real
  request is unknown and the server has an alternative (a `…Legacy` action); calls through a global client are
  recorded like any other request.

### 4. Codex's session-start hook

- **Trust that lasts:** KnowCode keeps its hook's definition and position stable, so trusting it once holds across
  updates and re-runs of setup, and never re-keys the user's own hooks (fixed for 0.4.0).
- **Says whether it's active:** `setup codex` and `knowcode status` read Codex's trust state and give the exact
  one-time step when it's needed. KnowCode never records trust on the user's behalf.
- **Measured:** confirmed in a real Codex session that the line reaches the model.

## Not in 0.5

- Windows.
- `path` and `flow` across library boundaries (impact and incoming trace only).
- Paused feature targets beyond history and co-change.
- A paid agent study per release.

## Release

- **Per pull request:** the usual gates, plus the replay subset.
- **Clean-machine acceptance** on Linux and macOS, including unprompted sessions.
- **Updates:** a cross-version update from 0.4.0.
- **Evaluation:** the gate's measurements and the milestone study are linked from the release notes.
