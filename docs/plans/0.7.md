# KnowCode 0.7 plan

October 29, 2026. About five weeks of work, run alongside 0.8.

KnowCode is open source and local-first. It has no hosted service, no paid tier and no model in the product. It aims
to cover about 95% of what the large code-intelligence products offer, with a local equivalent for each feature that
those products host. Every feature counts only once its gate passes, a gate that makes no model call. 0.7 is the
first step toward that, aimed at the gap that costs the most adoption: languages. It adds Go, Java and Kotlin, each
with its server routes linked across repos. It also fixes the identity condition 0.6 shipped without, and it publishes
the first answers-only comparison with two other open-source code graph tools.

What 0.6.1 left open:

- **Outside labels still linked.** The identity gate's condition "no link to an indexed declaration where the
  toolchain resolves outside the workspace" failed in 0.6.0 and again in 0.6.1, with no change: C# 6, Swift 22,
  TypeScript 37 ([0.6.1 gate](../../eval/release-gate/0.6.1.md)). Nearly all are `unique_name` links: the repo
  declares a name once, and KnowCode links it where the toolchain binds a library's member of that name. Each one is
  listed by cause, with its fix, in [0.6.1: outside labels linked](0.6.1-outside-links.md). That work moved past 0.6.1
  and is 0.7's first item. Three of the ten wrong `exact` links in 0.6.1 come from the same causes.
- **Go, Java and Kotlin aren't read.** [Languages](../languages.md) lists them as not supported. No answer covers a
  repo written in them, and their routes link to nothing.
- **A new worktree from a shared base hashes every file.** Cloning a base resets every file's stat
  (`checkout_reset` in `crates/kc-index/src/base.rs`), so the first sync hashes every file, including the ones git
  already knows are unchanged since the base's commit.
- **No published comparison.** No evaluation compares KnowCode's answers with any other tool's, so no comparison can
  be claimed in either direction.
- **The binary has less room.** 0.6.1 is 37,901,488 bytes, 0.39% over the 37,752,672 budget and within its 1%
  tolerance. Each grammar adds bytes nobody has measured yet.

## Gate

0.7 ships when these pass, compared with 0.6.1, and they are published with the release as
`eval/release-gate/0.7.0.md` (new file). None makes a model call. Labels come from a compiler, a framework's own
route table or git, always on public repositories, and never from KnowCode or a model. The one exception is the
client side of route links (below), which is labelled by hand under the neutral protocol's rules.

- **Tool cost per turn** for each profile: unchanged from 0.6.1 (`one` 501 tokens, `core` 1,276, `all` 3,377 with
  every tool loaded). 0.7 adds no op and no parameter. If the server's instructions name the new languages, the
  growth is stated in tokens and justified in the release notes.
- **Replay and history gates** as in 0.6: no regression beyond tolerance under both the strict and the call-site
  scorer, and history-v1 met in every part.
- **Identity, C#, Swift and TypeScript** ([identity-v1](../../eval/identity-v1/README.md), the same 4,943 labels):
  - **No outside label linked in any of the three languages:** the target is 0 in each, down from C# 6, Swift 22
    and TypeScript 37. If any label is still linked at the release candidate, the lead takes them to the user,
    listed by cause, and the user decides whether 0.7 ships with them listed on the gate page or waits for the fix.
  - `exact` precision stays at least 0.99 in each, and every wrong `exact` link is listed. 0.6.1 had ten.
  - Against 0.6.1, no label is newly wrong, and linked recall drops by no more than 0.005 in any language.
- **Identity, Go, Java and Kotlin** (identity-v2, new). References are sampled from pinned public repositories and
  labelled by each language's toolchain in a throwaway container: scip-go or gopls for Go, scip-java for Java, and
  scip-java's Kotlin support or kotlinc for Kotlin. As in v1, the set is weighted toward names declared more than
  once, and its README states the labelling rule. The README is committed before KnowCode's answers on the set are
  read.
  - At least 1,000 labels per language, over at least two repositories each.
  - `exact` precision of at least 0.99 per language, with every wrong one listed.
  - No outside label linked. This is required: a new resolver is built so that a name it can't tie to an indexed
    declaration stays unknown.
  - Recall, linked and among candidates, is reported per language.
- **Routes:**
  - **Server routes:** Go `net/http` (with method patterns), chi, gin and echo, and Spring's mapping annotations in
    Java and Kotlin. Each is labelled by the framework's own route listing, run in the container: gin's and echo's
    route lists, chi's walk, and Spring's handler-method mapping. Precision of at least 0.95 per framework, with
    recall reported.
  - **Client links:** precision of at least 0.95, on public repositories that have both a client side and a server
    side. The client sides are KnowCode's existing TypeScript and C# clients, plus the Go and Spring clients added in
    W1 and W2. These pairs are labelled by hand from source, under
    [LABELING.md](../../scripts/eval/neutral/LABELING.md), before and without KnowCode's answers. A seeded 20% is
    labelled twice, and the agreement is published with the results.
- **Grammar sizes:** `eval/size/grammars.md` (new file) is committed before any grammar is linked into the binary. It
  covers each candidate grammar alone and gives the bytes it adds to the dist binary. Each figure is reproduced within
  1% by a second build, and the build commit is recorded.
- **Binary size:** within 1% of `size-budget.txt`. The budget is raised only in a commit that links a grammar or
  grows the binary. That commit cites the grammar's measured bytes from the table, plus the extractor's own bytes from
  its own dist build.
- **Worktree first sync (perf #6):** a second worktree is cloned from a shared base, on each of the worktree gate's
  three public repositories. The first sync hashes only these files: the ones git reports as changed against the base
  commit, the ones that differ from their commit in the worktree, and untracked files. Instructions retired, plus
  `pread` and `statx` calls (counted on Linux), are reported against 0.6.1. The worktree gate passes on all 15
  worktrees with 0 mismatches. That includes the freshness cases, among them a same-size edit with its modification
  time restored.
- **Walks:** `crates/knowcode/tests/snapshots/walks.txt` is unchanged, unless a W6 fix needs its own reviewed bless
  commit.
- **Answer diffing:** the snapshot of `eval/queries.toml` (with its new Go and JVM sections) is taken against 0.6.1,
  and every difference is explained. A snapshot taken with `KNOWCODE_INSERT_REVERSED=1` equals one taken normally,
  for the new languages too.
- **Contract, task answers, worktrees, workspace gate, clean-machine acceptance with restricted mode, and an update
  from 0.6.1:** as in 0.6.
- **compare-v1, first results** (W5): the first results are published, under the conditions in W5's own check below.
  They don't change any gate item.

No comparative or benefit claim about agents follows from the gate. compare-v1 compares answers, not agents, and
supports only the figures it publishes.

**Feature rows this release closes:** languages, to Partial, by adding Go, Java and Kotlin. PHP, Ruby, C, C++ and
Objective-C come later. The gate page lists the row with its gate result.

## Work

Four workstreams, each with one agent: W1, W2, W6 (the work carried from 0.6.1) and W5 (its first half; W5 finishes
in 0.8). Before any change merges, it measures its own before and after on its gate set.

**Estimates.** The roadmap gave 4 agent-weeks to Go and 4.5 to Java and Kotlin, with 1.5 of those for server routes.
That figure didn't include the HTTP clients, which cross-repo linking needs. The clients add about half a week to
each workstream, so W1 is about 4.5 agent-weeks and W2 about 5. With one agent each, that makes 0.7 about five
calendar weeks rather than four. If W6 finishes early, it takes over W1's client forms.

### W1: Go, opening with the grammar size measurement (about 4.5 agent-weeks)

**Touches:**

- `go.rs` in kc-extract (new file), with one registration line in `crates/kc-extract/src/lib.rs`;
- `go.rs` in kc-store (new file), the resolution, with hooks in `crates/kc-store/src/query.rs` and
  `crates/kc-store/src/identity.rs`;
- `go.mod` in `crates/kc-extract/src/manifest.rs`;
- the Go parts of `crates/kc-index/src/test_targets.rs` and `crates/kc-index/src/test_select.rs`;
- Go routes and clients in `http_go.rs` in kc-index (new file), registered from `crates/kc-index/src/http.rs`;
- the Go labeller in a new `go` directory beside the existing ones in `scripts/eval/identity`, plus its image in
  `scripts/eval/identity/run.sh` and its repositories in `scripts/eval/identity/repos.txt`;
- `eval/identity-v2/` (new) and `eval/size/grammars.md` (new);
- the Go section of `docs/languages.md`.

**Order:**

0. **Grammar size measurement, week 1, before any grammar is linked.**
   - Use a throwaway branch that is never merged.
   - For each candidate grammar, build the dist profile once with that grammar added alone, referenced from code
     that runs so that LTO keeps it, and measure with `scripts/check-size.sh --no-build`.
   - The candidates are Go, Java and Kotlin, plus about 25 grammars for the later tags tier.
   - Build each candidate twice, and accept a figure only when the two builds agree within 1%.
   - Commit the table, ranked by bytes added, with the base commit and toolchain, before the lead's grammar PR.
1. **Labels first:** the scip-go or gopls labeller in the container, as `run.sh` runs the others (the image pinned
   by digest, and the network up only for `go mod download`). The repositories are chosen from candidates such as
   spf13/cobra, go-chi/chi and gin-gonic/gin, and pinned in `repos.txt`. From this point, every step measures its
   before and after.
2. Definitions, imports and packages: module paths from `go.mod`, and package-qualified names.
3. Calls and receivers: value and pointer receivers, embedded fields and promoted methods.
4. Implicit interfaces. A type satisfies an interface only when its whole method set matches. Without that match it
   is listed as a candidate, never `exact`. A generic instantiation is a candidate.
5. Tests and test targets: `_test.go`, `TestXxx`, `go test ./pkg -run '^TestXxx$'`.
6. Routes and clients.
   - Servers: `net/http` (`HandleFunc`, `Handle`, and method patterns such as `"GET /items/{id}"`), chi, gin and echo,
     with route groups and mounts.
   - Clients: `http.Get`, `http.Post`, `http.NewRequest` and `NewRequestWithContext`.
   - The route labeller runs each framework's own route listing in the container. The client-pair labels (gate)
     come from candidates such as go-gitea/gitea, whose TypeScript web client calls its Go API.
7. Docs: the Go section, the summary table and the "Not supported" line in `docs/languages.md`, and the help text.

What KnowCode recognises but doesn't read is reported as `unsupported`: cgo, generated files that aren't committed,
reflection-based routing, and build-tag variants beyond the default.

**Check:** identity-v2 Go, with `exact` at least 0.99, no outside label linked, and recall published. Go server routes
reach 0.95 against the frameworks' own listings, and client links reach 0.95 against the hand labels. Replay shows no
regression. The size budget is raised only in step 2's PR, the one that links the grammar.

### W2: Java and Kotlin (about 5 agent-weeks)

**Touches:**

- `java.rs` and `kotlin.rs` in kc-extract (new files), with registration lines in `crates/kc-extract/src/lib.rs`;
- `jvm.rs` in kc-store (new file), the resolution Java and Kotlin share, with hooks in `query.rs` and `identity.rs`;
- Maven `pom.xml` and Gradle `build.gradle` / `build.gradle.kts` in `crates/kc-extract/src/manifest.rs`, read as text
  and never evaluated;
- the JUnit part of `crates/kc-index/src/test_targets.rs`;
- Spring routes and clients in `http_spring.rs` in kc-index (new file);
- the scip-java labeller in the container, `eval/identity-v2/` for Java and Kotlin, and the docs section.

**Java and Kotlin count as one language family**, as TypeScript and JavaScript do. Each calls the other within a
module, so a name may resolve across them. They never resolve to another family. The invariant in
`crates/kc-index/tests/scope.rs` gains Go and the JVM family.

**Order:**

1. Labels: the scip-java labeller in the container, with the network up only for dependency resolution. The
   repositories are chosen from candidates such as google/gson and spring-projects/spring-petclinic for Java, and
   square/moshi (mixed Java and Kotlin) for Kotlin, and pinned in `repos.txt`.
2. Java definitions, packages and imports, including static and wildcard imports.
3. Java calls: receivers, overloads by arity, inherited members and interfaces.
4. Kotlin on the shared model: top-level functions, extension functions (applied only when the receiver type fits,
   which is the lesson of 0.6.1's C# cause B), companion objects and properties.
5. Maven and Gradle modules, for areas and test targets.
6. JUnit 4 and 5: `@Test` methods, with `mvn -Dtest=Class#method` or `gradle test --tests 'Class.method'`.
7. Spring routes and clients.
   - Servers: `@RequestMapping`, `@GetMapping` and their relatives, on classes and methods, in Java and Kotlin.
   - Clients: `RestTemplate`, `WebClient`, `RestClient` and `@FeignClient` interfaces.
   - The route labeller reads Spring's handler-method mapping in the container. The client-pair labels come from
     candidates such as jhipster/jhipster-sample-app (an Angular client) and
     spring-petclinic/spring-petclinic-microservices (Java to Java).
8. Docs.

Generated members (Lombok, annotation processors, Kotlin compiler plugins) aren't seen. Where KnowCode recognises the
annotation that generates them, the answer says `unsupported`, so a missing getter is never a confident absence.
Spring dependency injection isn't in 0.7.

**Check:** identity-v2 Java and Kotlin, each with `exact` at least 0.99, no outside label linked, and recall published.
Spring server routes reach 0.95 against Spring's own mapping, and client links reach 0.95 against the hand labels.
Replay shows no regression. The size budget is raised in step 2's PR for Java and step 4's PR for Kotlin.

### W6: carried from 0.6.1, outside links and perf #6 (about 3.5 agent-weeks)

The fixes are those of [0.6.1: outside labels linked](0.6.1-outside-links.md). Each is measured with
`scripts/eval/identity_gate.py compare` (no label newly wrong, and no loss of linked recall beyond 0.005) and with the
replay gate before it merges.

**Touches:** in kc-store, resolution in `query.rs`, `identity.rs`, `ts.rs` and `csharp.rs`. In kc-extract, `await`
and `#if` recorded in `swift.rs`, and bare specifiers in `typescript.rs`. `crates/kc-index/src/base.rs` (perf #6).
Perf #7, `task`'s repeated walk, isn't here: it is 0.8's, where `review` reuses the shared walk.

**Order:**

1. **Low-risk causes, by the end of week 1:**
   - A1, receivers rooted in a package import (TypeScript);
   - B, the `this` type of C# extension methods, with instance members first;
   - C, no file-name guess for a bare import;
   - D, a global type that isn't imported;
   - F, an unawaited Swift call never links to an `async` declaration.

   These clear about 42 of the 65.
2. **A2, standard-library member names with an unknown receiver,** measured against recall. This clears about 16.
3. **The four TypeScript locals of package types** (A's rest, such as `const { data } = useQuery(…)`): a local bound
   from a value rooted in a package import is itself rooted in it, so A1 covers it without full receiver typing.
4. **E, G and H**, which need new facts:
   - E: module-aware type names, read from the packages a Swift manifest declares;
   - G: a declaration's enclosing `#if os(…)` or `#if canImport(…)`;
   - H: outside protocols, extensions declared in test targets, and argument types against a repo extension on an
     outside type.
5. **Perf #6.** A clone of a base records each file's stat without hashing it when two things hold: git reports the
   file clean in the worktree, and `git diff --name-only <base commit>..HEAD` doesn't name it. Every other file is
   hashed, as now. `--verify` still hashes every file.
   - **Check:** the perf #6 gate item above. `crates/kc-index/tests/bases.rs` gains a case where a file changes
     between the base commit and HEAD with its size and modification time kept.

**Check:** no outside label linked in C#, Swift or TypeScript (or, at the release candidate, any left brought to
the user by cause, as the gate says), and the rest of identity-v1's gate as above. Answer
diffs are explained. Any walk change lands in its own bless commit.

### W5: compare-v1, first results (about 2 of its 4 agent-weeks)

compare-v1 compares answers, not agents. The other tools are codebase-memory-mcp and Serena, and no others. It
doesn't touch the Rust crates.

**Touches:**

- a new `compare` directory in scripts/eval: one adapter per tool, the question mapping and the scorer, standard
  library only, with tests;
- `eval/compare-v1/` (new): the mapping, the pinned tool versions and image digests, and the results;
- a container definition for the tools.

**Order:**

1. **Pin the tools and build the image.** Each tool is run twice over: at a pinned version, and at its latest
   release when the run starts. Both versions and the images are pinned by digest, and both results are published. The network is up
   only while the image is built and while each tool indexes, in case it fetches what it needs. It is cut before any
   question is asked.
   - Third-party code runs only in this throwaway container, never on the host.
   - KnowCode runs in the same container, so all three tools see the same files and the same CPU and memory limits.
2. **Commit the question-to-tool mapping before any run.**
   - The questions are references, callers, impact, find, locate and task.
   - For each question, the mapping names the call each tool's own documentation recommends, and each tool indexes
     the way its documentation says.
   - A question a tool has no call for is a "no counterpart" row. It is never scored as a win for the tool that has
     one.
3. **Adapters** that speak MCP to each tool over stdio and normalise its answer to `path:line` sets.
4. **Score against labels no tool made.**
   - References come from identity-v1, and from identity-v2 once W1's and W2's labels exist.
   - Callers, and impact two hops deep, come from the same toolchain enumerations, joined transitively.
   - Task and locate questions come from tasks-v1, and history questions from history-v1.
   - Scores are precision and recall, with counts and Wilson intervals, per language and per question type. "Can't
     answer" and tool errors are counted apart from wrong answers, with their logs kept.
5. **Run twice** on the 0.7 release candidate, and check that the two runs give identical scores.
6. **Publish with 0.7:** references and impact on C#, TypeScript and Swift, plus Go and Java if their labels are
   frozen by week 3. Every miss is listed, KnowCode's included, and the page is linked from `docs/evaluation.md`.

**Check:**

- the mapping's commit predates the first run;
- two runs give identical scores;
- third-party code ran only in the container;
- every miss is published;
- the wording claims nothing beyond the published figures: no "beats" and no "better than".

## Risks

- **Grammar size.** The three grammars' cost is unknown until week 1's table, and the tags tier's 25 come after
  them. If the table shows a cost the user wouldn't accept, the grammar PR waits for the user's decision. Measuring
  first is there so that this happens before anything is committed.
- **Grammar crates against tree-sitter 0.27.** A grammar crate that targets another ABI is pinned or vendored in the
  lead's PR. That could cost days.
- **Building third-party JVM projects to label them.** Gradle and Maven builds are slow and can fail offline. The
  candidates are picked to build after a one-time dependency restore, and a repository that won't build is replaced
  before its labels are read, never after.
- **The estimates.** W2 at about 5 agent-weeks sets 0.7's length. If Kotlin runs late, Java ships first and
  Kotlin's routes wait for 0.7.x only by the user's decision.
- **Implicit interfaces in Go** can make walks wide. Candidates stay leaves unless `evidence: all`, as ambiguous
  dispatch does today.
- **Zero outside labels may be out of reach for Swift.** E needs the packages' declared types, which KnowCode
  doesn't read today. Any label still linked at the release candidate goes to the user by cause, as the gate says.
  W6 reports its count weekly, so that this isn't a surprise.
- **A2 costs recall.** It is measured, and it merges only within the 0.005 bound.
- **W6 and W1/W2 both touch resolution** in `query.rs` and `identity.rs`. W6's first group lands first, and W1 and
  W2 keep their resolution in their own files.
- **compare-v1 may show KnowCode behind** on some questions. It is published either way, with every miss.
- **Load.** Performance figures are instruction and system-call counts, which hold under load. Wall-clock time
  comes only from a quiet machine.
