# C# compiler context selection

This adapter slice implements the C# variant of analysis policy 1 from [FIRST_WAVE_CONTRACT.md](FIRST_WAVE_CONTRACT.md). Shared settings/coordinator integration is owned separately; direct framed requests establish the worker behavior below. Legacy requests retain their selected configuration string.

With a present policy, absent configuration leaves the MSBuild Configuration global property unset. Projects evaluate their own repository/SDK defaults; a nonempty workspace override selects that configuration explicitly. No Know Code-wide Debug default is injected. Every declared framework is still planned and analyzed.

The selected SDK's `SolutionFile` parser handles `.sln` and `.slnx`. A selected `.slnf` resolves its base solution for mappings and remains a tracked input; its project list does not exclude other indexed projects. Discovery skips normal generated/reference directories and directory symlinks. Zero solutions means direct project evaluation, one selects it, and multiple solution files require an explicit selection. Missing, malformed or incompatible selection fails visibly rather than substituting another solution.

The isolated SDK helper evaluates MSBuild's generated solution wrapper, including `Directory.Solution.props`/`.targets` properties and imports. Solution-to-project mappings preserve effective Configuration **and Platform**, including differing labels. Standard solution globals and `CurrentSolutionConfigurationContents` accompany mapped project evaluation, metadata, restoration and compiler loading. Projects outside the solution evaluate their own defaults (or the explicit workspace configuration override). The helper uses `BuildManager`, the standard SDK `ValidateSolutionConfiguration` metadata target and `ProvideProjectStateAfterBuild` to obtain evaluated wrapper state without requesting default Build, compilation or external codegen targets. Standard SDK `InitialTargets` and validation hooks can still execute, as with other normal MSBuild metadata/restoration hooks; this is not a promise of zero target execution. Build/CoreCompile targets are not requested. InitialTargets behavior is exercised explicitly by the fixture rather than hidden behind an evaluation-only claim.

The isolated SDK metadata helper receives the same standard solution globals. It rejects unrelated property keys, includes effective Configuration/Platform in target metadata, records evaluated import paths, and caches per path plus selected properties rather than path alone. Restore checkpoints bind selected properties and SDK/input identities. Unchanged successful outputs reuse preparation; changed mappings/settings/import fingerprints require preparation again. Standard metadata evaluation remains separate from full builds and external code generation.

Compilation options expose requested/selected context, selection origin, effective configuration/platform, compiler metadata and assembly identity. IDs remain opaque: effective AnyCPU contexts retain the previous ID shape, while other platforms have distinct identities. Project reference witnesses use actual compiler CompilationReference identities and matching snapshot fingerprints.

Roslyn's known-project map can warn and fall back to a path-matched project when a consumed configuration is unavailable. The adapter avoids offering a mapped dependency to a caller outside that solution, and avoids reusing incompatible evaluated defaults. A compiler-selected dependency context absent from the indexed contexts is retained for correct caller compilation but reported as a project-loading boundary; it gets no inferred body link to a different indexed context. Supporting every extra configuration of such a dependency is outside this one-context slice. This conservative boundary is distinct from an ordinary symbol's third-party external boundary.

Focused verification uses `node tests/sdk-metadata.mjs` and `node tests/csharp_context.mjs` after protocol generation and an isolated provider build. The context suite requires local Roslyn/MSBuild pipe permission. It retains framed messages and source fixtures under `.artifacts/csharp-context/`, with the latest summary at `.artifacts/csharp-context/latest.json`. Cases cover repository defaults, override presence, every framework, mapped configuration/platform, outside projects, exact reference witnesses, ambiguity/missing selection, preparation reuse, mapping/import changes, `.slnf`/`.slnx`, wrapper properties/imports, normal InitialTargets behavior, partial graphs and no requested full build. Coordinator invalidation and assembled project-link/dispatch regressions remain integration checks, not proved by the direct-worker suite.
