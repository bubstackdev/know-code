# Polly compiler-resolution investigation

The corrected provider published Polly generation 7 with **59 complete** project/target compilations, up from 40 complete and 19 partial. All 59 declared contexts remain represented; no target was skipped. Source remained at the pinned corpus revision. See [corpus setup](CORPUS_FINDINGS.md) and [upstream reference pins](../.research/source-references.json).

## Provider defects fixed

The previous provider supplied `TargetFramework` as a workspace-wide global property. That also affected referenced projects: a net9 caller could load a dependency as net9 even though the dependency declared net10/net8/older targets and MSBuild selected its net8 reference path. The disagreement caused unresolved metadata paths, missing types, and false argument-resolution errors. Compatible legacy targets could also emit misleading loader warnings around implementation-only outputs.

The adapter now lets Roslyn/MSBuild discover project variants using the workspace configuration, without forcing one framework across the reference graph. It preloads dependency project inputs into Roslyn's public `ProjectMap`, then loads parents against those known outputs. This also uses Roslyn's existing implementation-output matching for older targets with no separate reference assembly. Know Code does not implement a framework-compatibility algorithm, invent assembly output paths, discard loader warnings, or modify upstream project files.

A catalog retains lazy project descriptions for the active worker request. For each declared root target, a separate `AdhocWorkspace` receives only that target's transitive project closure; compiler analysis/source-generator output is emitted, then the workspace is disposed. The catalog is never asked to compile all variants. Metadata is reused across requested projects; compiled target graphs are not intentionally retained together. This is a lifetime policy, not a numeric memory-cap guarantee.

Root variant selection records explicit `(project path, target)` ownership when contexts are loaded. When all evaluated identity properties match across a project's targets, one Roslyn call loads its variants. That fast path accepts only a complete, unique mapping using the pinned Roslyn 5.9 loader's `basename(TFM)` discriminator. Differing identity properties or an ambiguous mapping use separate target loads with fresh root ProjectIds. Failure to select an explicit context remains an error. Output paths are not used to guess a root target because projects may share output paths. Coverage `analysis_options` records the selected project context, actual root assembly identity, and direct referenced project contexts.

## Verification

[resolution.py](../tests/resolution.py) exercises a net10 caller binding to a library's net8 API, a netstandard-only caller binding to its netstandard API, all declared targets, extern aliases, Release configuration, and centralized artifacts. No dependency DLLs are built. Its [retained result](../.artifacts/resolve/latest.json) records the contexts; the previous forced-target loader fails this regression.

Isolated probes also compiled Polly.Core.Benchmarks/net9 against the net8 project variants and Polly.Extensions/netstandard2.0 against Polly.Core/netstandard2.0 with no loader/compiler errors. Initial diagnostics are retained in [before.json](../.artifacts/corpus/polly-resolution-before.json); the intermediate 58/59 result is retained in [after.json](../.artifacts/corpus/polly-resolution-after.json). The [complete result](../.artifacts/corpus/polly-resolution-complete.json) includes the final assembly-identity fix and all 59 complete contexts.

## Assembly-version gap fixed

Snippets/net10 previously reported five CS1705 diagnostics from one assembly-identity problem. Its restored Microsoft.Extensions.Http.Resilience dependency expects Polly assemblies with major assembly version 8; design-time project loading exposed version 1.0.0.0 because MinVer excludes `DesignTimeBuild=true`.

The adapter now evaluates the SDK's standard `GetAssemblyVersion` target for each project/target with the selected SDK/configuration. It passes the returned Version, AssemblyVersion, FileVersion, and InformationalVersion properties into that project's inner compiler context. Referenced projects are preloaded with their own evaluated identities through `ProjectMap`, so a consumer's properties do not replace dependency identities. Root contexts are tracked explicitly by project path/target and fresh ProjectIds; batched selection uses the pinned discriminator with a complete, unique mapping, while separate loads retain explicit target ownership. Output paths never guess a root target.

On the pinned Polly clone, SDK evaluation returned Version `8.7.0-alpha.0` and AssemblyVersion `8.0.0.0`. The shallow clone's configured minimum-version evidence is enough to calculate this identity; missing tags were not the cause. No assembly version was guessed or assigned from dependency expectations. The generated compiler inputs reflect the SDK-derived properties, and coverage exposes them under `analysis_options.compiler_metadata` alongside the actual compiled assembly identity.

This preparation runs the standard identity target, not Build/CoreCompile or arbitrary external codegen. Project/package versioning hooks attached to the identity target execute as part of that calculation. No Polly source edits, full builds, fetched history, compiled dependency DLLs, or diagnostic suppression were used. All compiler and loader diagnostics remain part of coverage.

The resolution regression also includes a version target intentionally disabled during design-time builds, mirroring this failure mode. It checks consumer identity 2 and dependency identity 8 independently, as well as framework selection, aliases, and no produced DLLs. Property and identity evaluation now use short-lived per-project SDK batches through the selected SDK's public APIs, with a fixed invocation directory and fresh project/import state per target. The earlier whole-worker API experiment was removed because its process-wide reserved `MSBuildStartupDirectory` crossed project scopes; the per-project boundary preserves that state correctly. Consolidation instead targets Roslyn calls for equivalent per-project variants and redundant discovery, preserving SDK evaluation for every target. Actual returned project inputs identify missing dependencies; they receive independent contexts before the root is reloaded. Managed generator console output routes to stderr to protect framed stdout. See [performance observations](INDEXING_PERFORMANCE.md). The adapter evaluates identity metadata once per context per worker job; persistent metadata memoization awaits complete invalidation for version-control/tool inputs. Git-only version changes still require an explicit refresh under the prototype's broader external-input limitations. These performance/invalidation limits do not justify hiding compiler errors or reusing guessed identities.
