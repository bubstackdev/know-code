# Call and impact query implementation plan

Status: **first end-to-end slice implemented**, with explicitly partial TS/C# call/dependency/dispatch coverage. Compiler workers emit source-backed relationships; SQLite format v6 preserves evidence and project-definition pointers; shared Rust `callers`, `callees` and `impact` operators serve the CLI and both in-process bindings. This is not complete v0.0.1 graph acceptance. Compiler-selected TS/C# project-body links are implemented; compiler-selected cross-project dispatch is implemented for supported ancestry/specializations; broader dispatch/implicit-operation coverage remains unfinished.

## Implemented slice

Worker/control protocol v7 retains relationship resolution, source artifact/byte range, implicit-call flag and dispatch form, plus capability-specific reports. Unknown targets remain nullable evidence, without a fabricated target symbol. Formats v2/v3/v4/v5 remain readable; old relationship triples migrate as `legacy_unknown`, never compiler-proven calls. Readers pinned before migration/publication retain their original snapshot. Endpoint/artifact foreign keys have cleanup indexes.

The TypeScript adapter records direct function/method/constructor/tagged calls, file/module and variable/property initialization contexts, accessor calls, and value/type/import/inheritance evidence. A resolved signature alone does not identify a function-valued variable's runtime target: mutable callbacks and aliases of function values remain unresolved unless the binding directly owns a constant function literal. Ordinary import aliases resolve through the compiler. Synthetic accessor/constructor/lambda/initializer identities stay within the provider; Rust does not interpret their ID strings.

The C# adapter walks Roslyn executable operation trees once per root, changing ownership inside lambdas/local functions. It records ordinary/constructor calls, property/indexer accessors, overloaded operators/conversions, interface/virtual binding and explicit override/implementation evidence. Delegate/dynamic/invalid invocations retain unresolved callsites. Fields/constants, type references, imports and inheritance use semantic bindings. Field/property initializers have separate execution nodes; lambda declarations retain source locations.

Rust matches possible call targets to compiler-proven override/implementation ancestry, preserving the original callsite, specialization and candidate proof. Cross-project matches require the exact composition/snapshot evidence described below; names alone never establish a path. All tested queries use the same source-version-bound relationships, filters and generation in Rust/.NET/Node.

Example: `{"op":"impact","symbol_id":"<opaque ID>","kinds":["call","reference"],"max_depth":5}`. Focused callers/callees accept call edges only. `include_implicit:false` excludes implied calls; `exact_only:true` excludes possible candidate edges without asserting concrete runtime execution. `paths_per_symbol` defaults to one and can request up to eight simple evidence paths. Path edges remain in source-to-dependency direction; reverse impact results are ordered from the changed seed outward, with each edge's explicit source/target preserved.

Initial operator defaults are implementation choices, not accepted performance guarantees: depth 1 for callers/callees and 5 for impact; 10,000 examined edges; 2,000 visited nodes; 100 result symbols; 1 MiB of materialized finding/path/evidence accounting; and 1 second of traversal work. Request bounds are depth 32, 100,000 edges, 20,000 nodes, 1,000 results, 8 MiB and 10 seconds. Required coverage/envelope metadata is outside that byte accounting; these are not total host-memory or serialized-response caps. SQLite work is bounded by indexed adjacency and row limits; a traversal-time check is not a hard SQL interrupt/deadline guarantee. No full-graph in-memory cache is loaded. Additional shared resource enforcement and total-response budgeting remain open.

Search limits are explicit in `graph.limits` and overall `truncated`; already discovered frontier evidence remains eligible for bounded projection. Traversal prioritizes paths without possible edges before possible paths, then fewer hops. It does not claim a stronger path is absent when budgets cut search short. Adjacency has no unbounded sorting step before its row limit.

Compiler `complete` status and graph capability coverage are separate. TS/C# currently report `calls`, `dependencies`, and `dispatch` as **partial**. Older indexes and Swift/Rust adapters have unknown graph capabilities, even when their implemented symbol/reference analysis is complete. External or other-compilation bodies are explicit boundaries. Unresolved incoming runtime targets cannot be attributed to an arbitrary changed symbol; partial capability coverage remains visible.

Current limits include open-generic/variance dispatch, TypeScript structural implementation discovery, some compiler-lowered implicit operations (including await/foreach/disposal), initializer-to-constructor runtime sequencing, broader generated/mapped-source coverage and combined cross-target presentation. No whole-program data flow or runtime/test-execution proof is claimed. Historical design sections below describe remaining work as well as implemented contracts.

Verification: [Rust graph tests](../crates/core/tests/graph.rs) cover path preference, cycles/budgets, multiple sites, unresolved/implicit/dispatch evidence, malformed ingestion, pinned readers and v3 migration. [Real compiler/native regression](../tests/call_graph.py) covers TS/C# saved changes, compiler-error partial publication/repair, exact UTF-8 sites, kind filters and all three query entry points. Results remain under [`.artifacts/call-graph/`](../.artifacts/call-graph/).

## Compiler-selected project bodies

Protocol v6 adds selected project-reference contexts, compilation input fingerprints and optional exact definition pointers on reference symbols. Store v5 persists those fields with an index on definition context/ID. Public symbol IDs remain opaque and compilation-owned; the core does not parse IDs or match names/signatures/assembly output filenames. Formats v2/v3/v4/v5 remain readable and migrate lazily without fabricating missing links. Pinned readers keep their pre-upgrade facts/source.

C# maps actual Roslyn `CompilationReference.Compilation` objects to the selected project/target contexts in the existing active dependency closure. Assembly-symbol equality identifies the referenced compilation; documentation IDs use original generic declarations. A snapshot hashes context, configuration/restoration epoch, compiler/SDK, semantic options, source-tree checksums/parse options, recursive compilation references and metadata module identities. Unknown or ambiguous compiler contexts yield partial `project_links` coverage and no speculative pointer. This does not build dependency assemblies or open a second compiler workspace.

TypeScript enables the compiler's source project-reference redirect through its compiler host, respecting `disableSourceOfProjectReferenceRedirect`. Effective analysis options expose that choice. The resolved reference tree supplies source ownership and selected config contexts; referenced sources belong to their own compilation instead of being copied into the consumer's graph. Shared declaration identity construction makes pointers exact, including the existing single-declaration-root rule. Missing/ambiguous reference ownership, undeclared compiler-consumed first-party inputs or disabled redirects gives partial `project_links` coverage. No declaration-output build, synthetic config, name-based `.d.ts` matching or additional language-service engine is introduced.

The TS snapshot witness hashes compiler version, restoration/configuration epoch, selected options, saved declared source inputs (preferring compiler-captured text) and recursive selected project snapshots. It is **not** a content inventory of all external package files. Direct mutations inside restored dependencies and full transitive dependency integrity detection remain existing preparation limitations; mismatched independently selected compiler versions do not link. Source-redirect analysis is the compiler's source view, not a claim to reproduce every emitted declaration/build artifact. Referenced source that is also an explicit root stays owned by that root; ambiguous merged declaration ownership does not link.

At read time a pointer resolves only to a currently served, owned symbol in its selected compilation, with matching nonempty snapshot fingerprint, project path and complete reference-selection capability on both units. Missing, changed or unavailable bodies remain explicit boundaries (`definition_compilation_unavailable`, `definition_snapshot_mismatch`, `definition_body_unavailable`); ordinary package/binary symbols remain external boundaries. Compiler diagnostics and the partial call/dependency/dispatch capabilities remain independently visible.

Links canonicalize relationship targets for all shared graph operators. Edges retain their original compiler binding, callsite/dispatch proof, target compilation and `definition_link` provenance. Querying a linked reference symbol exposes `root_definitions`. Incoming queries on the owned body see linked callers. A target filter selects the query root; it does not discard a compatible dependency selected under a different framework (for example net10.0 consuming netstandard2.1).

Every traversed path carries an interned map of project paths to selected compilation contexts. Crossing a link merges the next compilation's selections; conflicting contexts stop at an `incompatible_compilation_context` boundary with both selections. This conservative policy can stop assembly-retargeting/unification cases rather than assert their equivalence. Traversal memoization includes the context set, preserving a compatible route when paths converge. Context count shares the node budget; existing edge/state/time/response budgets still apply. Selection maps are shared when unchanged, not duplicated per local edge. Possible dispatch also uses normalized implementation/override facts across projects under the compiler-selected composition rule below.

Adjacency streams use relationship endpoint indexes and the definition index. Base adjacency has two explicit SQL union branches; dispatch proofs use four explicit branches to normalize both endpoints. Ordered lookup joins prevent building a temporary automatic adjacency index before LIMIT. A core query-plan regression checks both directions. No graph-wide cache or separate linking/query engine is added.

Verification: [project-body integration regression](../tests/project_links.py) covers real TS and Roslyn two-hop bodies, exact multi-framework selection, compatible different-framework selection, reverse impact, generic declarations, TS constructors/implicit accessors, C# implicit accessors, package boundaries, saved edits, disabled redirects and Rust/.NET/Node parity. Core graph regressions cover snapshot mismatch, conflicting selections, convergence under different context sets, pinned readers and v4 migration. Detailed run evidence lives under `.artifacts/project-links/`; numeric performance guarantees are not inferred from fixture success.

## Cross-project interface and virtual dispatch

The user accepted a strict composition rule: **a cross-project candidate requires an indexed compilation that selects both the caller and implementation-proof compilation contexts**. Merely finding the same interface in unrelated projects is insufficient. Every selected reference in that witness must carry a nonempty input fingerprint matching its currently served compilation. The common core intersects compiler-consumer metadata, merges the witness/proof/binding/body context selections into the path ledger and stops at conflicting frameworks. An unavailable witness yields `dispatch_context_unproven`; it is not an affected-symbol finding or a traversable path. Multiple eligible witnesses remain separate traversal states even when default projection returns one path.

Compiler workers now emit ancestry facts, leaving matching, budgets, storage and traversal in Rust. Roslyn records every compiler-resolved overridden ancestor. Its interface mapping can name a base virtual slot; a per-type map of actual overridden methods selects the most-derived implementation in the analyzed receiver type. Inherited implementations keep the declaring body identity and the class's interface-mapping proof. Properties use their accessor methods. TypeScript uses explicit class/interface heritage, compiler property lookup, assignability checks and compiler base types, including interfaces declared by ancestors. It does not scan arbitrary structurally similar classes. Compiler extraction may record a verified ancestor relationship rather than only the immediate parent.

This representation avoids blindly composing method-level `implements`/`overrides` edges. For example, if `C : B, I` inherits `B.Run`, `D : B` must not become an `I.Run` implementation unless its own compiler analysis proves that relationship. The proof owner can differ from the body owner; both remain visible and participate in context checks. Explicit C# `base` and TS `super` calls/accessor calls stay direct.

Protocol v7 adds an opaque `dispatch_key` and selected-reference snapshot fingerprints. Store v6 persists the key and includes it in evidence uniqueness, preserving multiple specializations at the same site. Canonical declaration IDs remain unchanged: `IWork<int>` and `IWork<string>` cannot be distinguished solely by their shared declaration symbol. Calls match implementation proofs only when their nonempty compiler-produced receiver-specialization keys agree. Nongeneric keys are compact constants; closed generic keys are SHA-256 digests of compiler identities/arguments. C# includes argument assembly identities; TS uses compiler primitive/literal/named declaration identities, omits its implicit polymorphic `this` argument and avoids display-name matching. Per-file/per-program caches keep repeated key construction bounded to compiler analysis lifetimes.

Open/unprovable receiver specializations and unsupported anonymous structural arguments remain unknown; outgoing queries retain their compiler binding and report `dispatch_specialization_unproven`. Exact key equality is deliberately conservative: open generic implementation instantiation, generic variance/conversion matching, all structural TS implementations, default-interface/reabstraction details, all lowered implicit operations and runtime receiver flow remain incomplete. Call/dependency/dispatch capabilities stay partial. A labeled possible declaration/body is not proof of runtime execution.

The Rust operators inspect base adjacency and normalized implementation facts through indexed lookups. Proof inspection and call lookup consume the **same query edge/time budgets** as ordinary traversal; response/context/state/node limits also apply. There is no per-call fresh budget, recursive SQL ancestry scan, graph-wide cache or second execution engine. Schema v5 and older facts have no specialization proof; migration leaves keys empty rather than fabricating candidates. Bound declarations and compatible body links remain queryable, and pinned readers survive the transactional migration. Updated readers require refreshed specialization evidence for old locally inferred dispatch candidates too; they do not promote legacy declarations into proven generic-compatible targets.

A possible edge retains its callsite, original binding ID, binding definition link, dispatch specialization, compiler implementation proof (source/target IDs, kind, owning compilation, exact source location and endpoint definition links), plus the selecting composition ID/fingerprint. The existing `dispatch_evidence` location remains for consumers. The additional fields are shared by Rust, .NET and Node. `exact_only` excludes possible dispatch while preserving compiler-bound dependency evidence.

Verification lives in [compiler/native dispatch regression](../tests/dispatch.py) and core graph tests: sibling composition, unselected TFMs, transitive ancestry, inherited-body receiver safety, closed generic separation, reverse callers/impact, exact filtering, direct base/super calls, saved composition removal, stale witness snapshots, shared budgets and migration/pinned reads. Both endpoint directions have a query-plan gate against relationship scans, automatic index materialization and temporary sorting. Detailed run evidence belongs under `.artifacts/dispatch/`.

## Accepted behavior

- Callers, callees and dependency impact are required in v0.0.1, through the same Rust operators for native libraries, CLI and eventual MCP.
- Impact follows **compiler-backed calls, type references, inheritance and imports by default**, with dependency kinds labeled and filterable. Callers/callees remain call-specific. A text-search match is not a semantic dependency edge; external/unresolved boundaries remain visible.
- The user additionally accepted **value references**, including field/constant reads, in default impact traversal, distinctly labeled. Structural containment/initialization and implementation/override evidence connect the recorded dependencies and remain filterable too.
- References and calls remain distinct. Every call retains caller/execution context, source-version-bound callsite and compiler binding evidence. Unknown targets remain unknown.
- Include possible interface/virtual targets by default, label them as possible, and support exact-target-only filtering. A compiler-bound interface member is not proof of a runtime implementation.
- The user accepted **implicit calls included by default**, explicitly labeled and filterable: property accessors, overloaded operators and conversions belong alongside explicit invocations. This does not promise reconstruction of every compiler-lowered runtime operation.
- The user accepted **explicit, labeled initializer nodes** for file loading/type initialization. Initializer execution must not be conflated with later uses of a field or function value.
- Impact results show **one supporting path per affected symbol by default**, with additional paths available on explicit request under the shared query budgets. Prefer a compiler-bound path over a shorter path containing possible dispatch. One path does not imply uniqueness, and compiler binding does not prove runtime execution.
- Preserve coherent generation, target provenance, partial coverage, stale fallback and source projection. Traversal must never join incompatible compilation contexts into a fabricated path.

## Minimal shared contract changes

Keep five logical fact families. Extend relationships rather than introduce a second call store or a per-language query engine. The shared evidence envelope must cover the accepted call, type-reference, inheritance and import kinds. A call relationship needs its source/execution owner, optional target, kind, resolution category, implicit flag and artifact/UTF-8 range; other dependency kinds retain their own compiler/source evidence without pretending to be invocations. A known compiler-bound declaration, a possible dispatch candidate and an unresolved callsite must remain distinguishable. Multiple callsites between the same endpoints must not collapse into one evidence-free edge.

Store callsites with no known target as source-backed evidence; do not manufacture an `unknown` symbol just to satisfy a foreign key. Validate IDs/ranges and resolution combinations once at the ingestion boundary. Existing endpoint-only relationships require a compatible migration/unknown-evidence representation; older facts cannot become compiler-proven calls merely because a new query operator exists.

Populate enclosing execution context from compiler syntax/operations. Named/local functions and lambdas need distinct usable identities. File/module/type initialization needs an explicit execution context: assigning an initializer's calls to a field/function-value symbol must not imply that every later use executes the initializer. Static declaration identity and instantiated display types stay separate.

The current provider symbol IDs include compilation identity. Following an endpoint into another project's body therefore also requires explicit compiler-compatible context links and a semantic declaration key. C# project-reference target negotiation must select its actual referenced target, not all targets with the same name. TypeScript project-reference outputs/redirects need compiler evidence too. Preserve a boundary when a body/context cannot be linked; name/signature matching is insufficient. Cross-workspace linking remains v0.0.2 work.

Analysis reports need capability-specific coverage for these new operators. A Swift symbol/reference report or older TypeScript report without call extraction must not be interpreted as complete call coverage. Missing/unsupported capability metadata means unknown/unavailable, never zero calls.

## Narrow compiler adapters

C#: consume Roslyn operations for invocations, object creation, accessors and overloaded operators/conversions, retaining compiler target and implicit evidence. Visit each executable operation tree once rather than querying operations for every syntax node. Delegate/dynamic calls need honest indirect/unresolved boundaries; the delegate's declared `Invoke` method is not a discovered concrete function body. Extract declared override/interface implementation evidence for shared possible-dispatch expansion.

TypeScript: use resolved call/new signatures and compiler declaration roots. Imports/aliases, methods, constructor signatures, local functions and lambdas need exact occurrence evidence. A function-valued variable/parameter and its callable type are not automatically the identity of a concrete runtime implementation. Preserve such indirect boundaries without inventing whole-program data flow. Structural typing makes explicit `implements`/override evidence an incomplete inventory of possible runtime receivers; retain that coverage limit.

Workers supply compiler facts, not graph traversal, storage or a second dispatch engine. Rust uses recorded implementation/override evidence to perform bounded possible-target expansion under the same query budget.

## Shared Rust operators and verification

Add focused `callers`, `callees` and `impact` projections over one internal adjacency/walk implementation. Bound rows, depth, visited nodes/edges and response bytes; retain path evidence and report truncation/boundaries. Exact request field names and numeric defaults are implementation decisions still open. This design does not add textual graph syntax or expose SQL.

Accepted path preference applies within those budgets; it does not authorize exhaustive path enumeration. Preserve a valid discovered path when search is limited, including its possible-dispatch evidence, and expose the limit. Failing to find a compiler-bound alternative within the budget is not proof that none exists. Traversal/tie-breaking mechanics remain open; the preference must be shared by all entry points.

Use real compiler regressions where reference counts would hide a wrong graph: a reference without invocation, overload/extension/local-function/lambda calls, recursion/cycles, explicit versus implicit calls, virtual/interface candidates, unresolved/indirect calls, multiple callsites, generated source and incompatible target contexts. Check in-process Rust/.NET/Node parity, source ranges, atomic replacement and migration. Measure compiler extraction/graph query cost on the existing corpora rather than treating tiny fixtures as performance gates.

Implementation order: shared evidence/coverage contract and storage migration; TypeScript/C# extraction; common bounded operators/native parity; compiler-compatible cross-project traversal and dispatch evidence. This order describes development slices, not permission to release incomplete required v0.0.1 behavior.
