# TypeScript test-origin evidence

This adapter implements policy 1 from [TEST_CLASSIFICATION.md](TEST_CLASSIFICATION.md). It annotates saved compilation/source facts; shared Rust storage, declaration aggregation, filtering, cursor scope and policy backfill belong to the common core.

Compilation classification defaults to `unknown`. Each owned source receives explicit `test` or `unknown` metadata for its normalized root-relative path. A case-sensitive `__tests__` directory component matches; otherwise a `.test`/`.spec` suffix before an existing compiler-consumed TS/JS script extension matches (`ts`, `tsx`, `mts`, `cts`, `js`, `jsx`, `mjs`, `cjs`). A filename such as `name.test.d.ts` does not match that suffix rule, while declarations inside `__tests__` still match the directory convention. Runner/global/symbol names and arbitrary runner configuration are never evaluated. An unrelated absolute ancestor named `__tests__` is not part of root-relative evidence.

Positive evidence records `basis:path_convention`, the exact rule and source path, and `inferred:true`. It is a naming inference, never proof of test execution or coverage. Unmatched origins remain unknown, including production helpers called by tests. Oversized matching paths produce explicit unknown/abbreviated evidence instead of an invalid positive label. The report capability is `test_classification:partial`, independent of compiler diagnostics/completeness and existing partial graph capabilities. All first-party sources/facts still emit.

`AnalyzeRequest.test_classification_policy` accepts 0 (legacy) or 1. The worker acknowledges the exact requested value in its initial provider message before facts; unsupported values fail before provider/fact output. Classification policy is independent of package preparation: it changes neither restoration epochs nor commands. Policy 0 preserves legacy compilation fingerprints/source facts without classification metadata. Policy 1 adds compilation defaults and each declared source's effective classification to every own/referenced project snapshot witness, so definition pointers agree with separately indexed child contexts.

Content bytes, SHA-256 and `path@SHA` artifact IDs are unchanged. A same-byte rename changes its path-derived artifact/symbol identities and classification through the ordinary saved-input path. Policy upgrades at unchanged paths require the common coordinator's policy backfill/invalidation; changing a worker-side snapshot alone cannot schedule a previously current workspace. Classification lives on compilation-owned origins, not globally deduplicated text.

Source-file module symbols and synthetic module/initializer nodes now receive deduplicated real owned declaration/definition ranges. This lets the core derive their origin evidence without guessing from calls, names or IDs. Existing symbols, IDs, calls, dependencies and reference occurrences are preserved; new anchors are additive and may change occurrence-count baselines and previously empty module/initializer source locations/context. Anchors never attach a referenced/external declaration to the current source artifact.

## Focused checks

`node tests/typescript_test_classification.mjs` uses small owned configured/inferred compiler programs, a local `2377774` adapter control and real protocol-7 workers. It checks conservative/oversized rules, TS/TSX/configured JS/declaration files, exact UTF-8 hashes/anchors, unchanged symbols/calls/references, old-occurrence preservation, cross-project snapshot equality, same-byte rename, fresh partial compiler graphs, exact legacy/current policy acknowledgment and unsupported-policy rejection. A runner-config side effect must remain absent. Dependency copies and evidence stay under the isolated worktree's durable paths.

Final execution/source-bound evidence is recorded at adapter handoff. This does not certify shared filters, mixed-symbol aggregation, traversal, migrations/backfill, native/MCP/package integration, performance or release readiness. The common integration gate must preserve unknown-inclusive exclusion and traversal through nonmatching helpers while filtering returned findings.
