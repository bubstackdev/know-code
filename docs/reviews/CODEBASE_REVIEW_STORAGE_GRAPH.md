# Storage and graph release triage

Reviewed 2026-11-11 against main `30dcea2fdae2c1017fc9ada293052acd385edfc6`. This is an independent read-only assessment of the storage/graph claims in `CODEBASE-REVIEW.md`, not an implementation or a fresh performance measurement. No tests, benchmarks, compiler jobs, native probes, migrations or live runtime changes were run. The original review was produced during active development; its line numbers and “nothing fixed” statement are not a current-state guarantee.

## Before tagging 0.0.1

The clearest small fixes are the three missing cleanup/FK indexes (H6/M14/M15), depth-frontier expansion (H10), and filtering the streamed adjacency before its row/work cap (H11). They address concrete hot-path defects without changing the graph engine or public query language. Bound symbol-search declaration materialization too (L21): its current all-declarations read happens before the response/projection budget can reject it.

The new WAL policy needs its focused assembled acceptance checkpoint before a tag. The initial M16 claim identified a plausible loop but did not trace the actual pause/resume state. The current code contains subsequent fixes; the remaining gate is proving those combined behaviors, including concurrent reclamation and preservation of reader/cursor generations. Do not treat the original claim as proof that the current source still loops, or a static fix as proof that the WAL gate passes.

These are this lane's recommendations. Other review lanes and the release ledger still determine the complete pre-tag list.

## Claim-by-claim assessment

| Claim | Current source evidence | Release classification |
| --- | --- | --- |
| **H6** missing `unit_artifacts(owner_generation, artifact_id)` | `store::SCHEMA` has PK `(owner_generation, compilation_id, artifact_id)`. `store::reclaim` probes owner+artifact while skipping the middle PK column. Artifact deletion also checks this child FK. The later idempotent index setup creates occurrence/relationship indexes but never this one. | **Fix before tag.** Add the exact child/probe index in shared write-schema setup. The original 78-second figure was not rerun here; the access-path omission is source-confirmed. |
| **M14** missing `artifacts(content_hash)` | `artifacts.content_hash` references `contents`, but available artifact indexes cover generation/id and path/generation. Deleting unused contents in `store::reclaim` requires unindexed child-FK checks against remaining artifacts. | **Fix with H6.** Add the child-key index. The original 4.9-second figure is unverified by this audit. |
| **M15** missing `generation_units(owner_generation, compilation_id)` | Its PK is `(generation, compilation_id)`, while compilation reclamation and its child FK use owner generation+compilation. Pinned manifests can retain repeated owner references. | **Fix with H6.** Add the owner-pair index. |
| **H10** frontier expansion | `graph::query` calls `dispatch::neighbors` after projecting a popped node, and only checks `distance >= depth` inside the neighbor loop. Before that check, dispatch work is charged and unresolved/specialization boundaries can be appended. | **Fix before tag.** Do not enumerate/prove beyond the requested frontier. If needed, use a bounded filtered existence probe to report a depth limit, preserving concrete contexts and already discovered findings. |
| **H11** filters after adjacency limit | `adjacency_sql` ordinarily filters generation+endpoint; its special virtual-call shape adds only its specific call/proof predicate. `dispatch::neighbors` applies SQL `LIMIT remaining+1`, calls `Budget::take`, then `accepted` checks kind/implicit/exact policy. Calls can therefore lose their edge allowance to rejected non-call rows. | **Fix before tag.** Push applicable edge predicates before the streamed row cap. Keep shared proof-work accounting and the existing no-full-scan/no-temporary-sort plan gates. An arbitrary `ORDER BY` that introduces a large sort would regress the accepted streaming design. |
| **M16** staging-WAL retry loop | `store::defer_checkpoints` deliberately disables auto/close checkpoints. The initial integration could count its own failed-stage WAL truncation as fresh progress. Current coordinator changes settle safe own maintenance before a durable active-pause baseline; deferred writer ownership uses `baseline_pending`; preflight deferrals now have no own-stage progress requirement. Allocated rebuild failures still take the explicit-retry path. | **Combined gate, not a blanket current-source defect.** Run the finite active-pressure/held-reader fixture and verify no repeated worker without real permission/progress, plus preflight reclaim/restart/cancel behavior. Preserve the first failed results. |
| **M17** 120-second candidate integrity deadline | `recovery::validate_candidate` sets a wall-clock progress handler and runs `PRAGMA integrity_check(1)`. The argument limits reported errors, not the amount of healthy data checked. Interruption is not classified as SQLite corruption; the prior selected index is not poisoned. An allocated failed replacement consumes its attempt by accepted policy. | **Scale/contention gate or later tuning.** Do not remove a bound or add automatic retries merely because the bound exists. Escalate to a blocker if a required release fixture cannot seal within the accepted resource/contention policy. A timeout should remain an honest failure, with compatible old data stale and explicit retry available. |
| **M21** no adjacency-result memo | `visits` is keyed by `(node, possible, context)` and permits up to `paths_per_symbol` visits. Each accepted visit fetches neighbors again. This preserves distinct path/context selection; adjacency SQL itself is already prepared with `prepare_cached`. | **Backlog pending measurement.** Repeated row reads are real, but an “8×” general slowdown is not established. A cache must remain bounded and must not collapse incompatible contexts or stop charging real proof/path work. No whole-graph cache or second walker is warranted. |
| **M22** graph 1 MiB vs response 256 KiB | `graph::query` has its own finding/path budget; `ProjectionBudget` and the common encoder enforce the complete envelope. Cursor materialization deliberately uses a larger aggregate allowance than an individual page. `QUERY_LIFECYCLE.md` explicitly accepts independent sub-budgets and typed `response_limit_exceeded`. | **Not a defect against the accepted contract.** Optional adaptive defaults are UX backlog. Do not silently remove required evidence or reduce the whole cursor result to one page to force success. |
| **M23** graph coverage is workspace-wide | `ReadView::query_inner` skips its relevant-coverage reduction when `result.graph.is_some()`. Graph construction also creates a capability entry for every compilation. | **Performance/response-size backlog.** Workspace-wide metadata is conservative evidence, not wrong graph identity. If required release workspaces cannot make useful bounded graph requests even with the allowed envelope, that concrete gate becomes a blocker. Any relevant reduction must retain root, path, support, boundary and compiler-consumer witness coverage, including empty/partial cases. |
| **M24** uncached point SQL | `graph::symbol_projection`, `testing::symbol_mask`, `testing::symbol`'s external lookup, `grouping::key`, and reference-origin lookup use some uncached point statements. Adjacency, location, extent and classification-evidence statements already have cached paths. | **Measured tuning backlog.** The blanket uncached-hot-path description overstates the scope. Re-run the accepted warm symbol/reference contention gate on final artifacts; change only evidenced preparation hotspots if that gate fails. |
| **M25** repeated line-prefix scans | `ReadView::source_line` streams 8 KiB chunks from the indexed blob's beginning, with health/deadline checks. Declaration projection always needs its declaration line. Source-body projection may call it again for the extent start, which can be a different offset. `include_source:false` still performs the declaration-line calculation, but does not universally perform two scans. | **Backlog, wording corrected.** Preserve UTF-8/NUL/CRLF correctness and exact saved-version coordinates. A small query-local `(hash, offset)` line cache is a possible measured optimization; a new line-index store is not required before tag. |
| **M26** all matches before limit | `symbols_sql` groups finding keys and orders by aggregate name/id/compilation before SQL `LIMIT`; that can scan/sort all matching keys. Rust collects only `limit+1` group keys, then uses the response/materialization budget for projected findings. Broad browsing is accepted by the current API. | **Performance gate/backlog; claim overstated.** This is SQL grouping/sorting work, not a Rust vector of all matching symbols. Existing exact-name/text query-plan and final contention gates matter. Do not remove target equivalence or browsing merely to simplify the plan. |

## Related low claims

| Claim | Assessment and minimum action |
| --- | --- |
| **L16** `Writer::drop` cleanup lacks cooperative cancellation | **Source-confirmed; gate after the index fixes.** Drop deletes unpublished staging/manifests then calls `reclaim` without a retained Control/progress handler. This can keep the writer fence while cleaning. First remove H6/M14/M15's pathological scans and test cancellation/failed staging with retained current and cursor data. If cleanup still wedges normal required work, bound or defer that same cleanup safely; do not turn cancellation into a second reclamation engine. Simply interrupting every cleanup with an already-cancelled token can leave pressure-producing data indefinitely. |
| **L17** `symbol_test_mask` “never usable” | The ordinary bit-mask predicates are not equality/range seeks on this single-column index. That does not prove SQLite can never choose it for any covering scan. **Plan/measurement backlog.** Remove only after inspecting actual relevant plans/write cost; not a release blocker. |
| **L18** no `compilations(project_path)` index | **Source-confirmed.** Incremental `Writer::open_target` searches project path when replacing manifest entries. The compilation table is much smaller than occurrence/artifact tables in ordinary use. **Cheap candidate/backlog**, or include with the small index patch if an actual incremental plan/workload justifies it. No independent large cost was established here. |
| **L19** repeated depth labels | **Source-confirmed, internal work only.** A label is appended per frontier neighbor and repeatedly scanned. The returned vector is sorted/deduplicated before return, so the final wire does not contain 100k duplicate labels. **Fix naturally with H10** and insert each limit reason once. No enum/framework is needed. |
| **L20** full context references parsed per graph request | **Source-confirmed.** `Contexts::load` loads current compilation contexts and parses references, needed for strict compiler-selected composition. These are not all symbol/edge facts. **Measured setup-cost backlog.** It must remain generation-bound, deadline-aware and preserve exact context witnesses; no global graph cache is justified. |
| **L21** `symbol_full` unbounded declarations | **Confirmed only on the symbol-search projection path.** `query_inner("symbols")` uses `graph::symbol_full`, collecting all declaration locations before charging `ProjectionBudget`. `symbol_context` and graph findings already use bounded `graph::symbol` with 16 locations plus lookahead. **Fix before tag:** bound compact search anchors too and expose honest truncation/declaration evidence for every affected concrete support. Do not change full anchor comparison in target-equivalence storage keys or drop supporting targets. |
| **L1** live/health mmap truncation | The size is checked before mapping; same-user external truncation afterward can still fault the host. Normal runtime writers do not truncate an active health page. **Hardening backlog** unless a supported non-tampering failure path is demonstrated. Do not install a global SIGBUS handler inside an embedded library as a speculative fix. |

## Minimal implementation and validation boundaries

- Add the three missing indexes once through shared idempotent write-schema setup. Cover current-format writes and supported compatible paths that can reclaim retained generations; repairing only newly created databases leaves old retained stores exposed. Index-only repair need not change compiler identities, fact encoding, worker framing or query contracts.
- Preserve transactional migration and existing pinned-reader/source behavior. A focused bundled-SQLite plan gate should prove the owner/artifact, content-hash and owner/compilation probes use the new indexes. Verify actual publication/release preserves FK coherence and old readers. Do not turn the review's diagnostic row counts/timings into claimed certified performance without rerunning their exact workload.
- For H10/H11, use an owned graph fixture with many rejected-kind edges before valid calls, plus dense depth-frontier adjacency/unresolved/possible-dispatch evidence. Assert valid in-depth results survive small edge budgets; no beyond-depth findings or diagnostics are produced; source/support contexts stay concrete. Retain existing dispatch/project-link plan gates.
- For L21, a single logical symbol with more than 16 declarations and equivalent target supports should remain a bounded search finding with explicit partial evidence. A low graph/query result count must not permit an unbounded declaration vector before projection accounting.
- Finish the existing finite WAL acceptance wave rather than duplicating it. Preserve raw-reader coherence, idle logical cursor retention, post-publication checkpoints outside cursor/entry/settings locks, one shared disk pool, explicit active-rebuild retry and safe preflight auto-resume.

## Storage architecture claims

**Architecture 4 — registry versioning:** Current coordinator startup has additive column checks and uses WAL plus `synchronous=FULL`. Some changes are explicitly transactional, and durable entry writes use a transaction. The absence of a `user_version`/ledger is real, but it is not evidence that current registration/settings writes lose durability. A small explicit registry schema/version boundary is sensible follow-up before incompatible durable-schema evolution; rewriting the registry into a new layer is not needed to fix H6 or graph behavior. Tag documentation should state the actually supported development upgrade direction.

**Architecture 5 — disk accounting in recovery:** The current budget deliberately reuses selector/incarnation ownership checks and physical-family paths. Moving it into a new module/type now would expand the change while the shared-pool wave is being validated. Keep the small public `DiskBudget`/`DiskUsage` seam; extract later only for a concrete dependency or reuse benefit. No separate budget engine or crate is justified.

**Architecture 9 — stale implementation status:** Confirmed. `IMPLEMENTATION.md`'s current-looking bullets still say new writes use v6 and describe pagination/admission as pending, while later historical checkpoints describe newer slices. Preserve historical evidence, but update the leading current-state summary and point to runtime/constant definitions before tag. Do not describe store8/query7/lifecycle3 as a full release certificate.
