# Snow Leopard architecture review dispositions

This is a source-based reassessment of architecture items 1/2/6/7/12 in [CODEBASE-REVIEW.md](../../CODEBASE-REVIEW.md), not authorization for new features or an architecture rewrite. It incorporates released pre-tag fixes and the root integration's compact query contract9 / cursor control3 work. Current values belong to their source constants; previously published evidence applies only to its exact recorded source/artifacts. No builds, native loads or compatibility tests were run by this reviewer.

| Item | Actual boundary and disposition |
| --- | --- |
| **1 — capability checks** | Ordinary control calls pass through `control::exchange` / `checked_response`, which enforce the current index lifecycle and typed peer errors. Workspace settings/cancellation paths additionally enforce settings/resource capabilities; cursor transport enforces its page-producer control contract and lifecycle; live-state reads validate the owner record version, PID/start identity, and lifecycle/settings/resource fields. The installer intentionally uses a restricted, directional bridge for known previous lifecycle peers and only status/maintenance/resume/shutdown. These are different safety purposes, not evidence that every operation should require every field. Existing control/live/cursor/Workspace fixtures cover named mismatches. No concrete newly uncovered unsafe peer acceptance was established here. A typed `Capabilities::require` framework is deferred; it would need to preserve these operation-specific requirements and installer directionality. |
| **2 — repeated version constants** | Rust's exported native query version is compared by both SDKs before query admission and before Workspace control; Workspace wrappers then delegate coordinator compatibility to the common Rust client. The absence of a second JavaScript/.NET coordinator-version comparison is not an absent handshake. Framing, store readability/migration/rebuild, lifecycle safety, settings/resource policy, cursor producer semantics and public query shape are separate contracts. Some wire constants remain repeated across Rust/Node/C#; generation is useful maintenance work, but combining unrelated numbers would not establish compatibility. The new **concrete missing matrix** is actual released SDK/native8 versus new compact SDK/native9; an explicit artifact-bound operator packet is prepared below. It is pending execution, not a passed check. |
| **6 — legacy native entry points** | Existing `query_json`, started/elapsed, cancellable, scoped and reserved wrappers remain public across their respective Rust/C/Node surfaces. They converge on common admission/execution rather than implementing another query engine. Native clients must honor the exported query contract; a raw C caller that never asks its expected version cannot be retroactively identified as an old SDK. Removing these entry points is an API/product decision requiring focused Q&A, not a fix for the resolved panic/ownership defects. Keep them during stabilization unless that decision is explicitly made. |
| **7 — operation strings / schemas** | The core request rejects unknown fields and dispatches a finite read-only operation set through common operators; invalid operations produce typed errors. Root CLI/MCP fixes validate their actual boundaries: focused MCP tools deny unsupported properties and operation overrides, and structured graph tools restrict `op` to callers/callees/impact. The root MCP review found no admission ownership/liveness blocker. An operation enum or wholesale schema generator is not required to correct a demonstrated remaining defect; retain the finite boundary regressions and use the common deadline constants when touching real duplicate literals. This does not claim all future schema drift is impossible. |
| **12 — dependency duplication** | Current `Cargo.lock` contains sha2 `0.10.9` for core/host and `0.11.1` through rmcp, with digest `0.10.7`/`0.11.3`. It contains syn `2.0.119` and `3.0.9` for procedural/build dependencies; the report's syn1/syn2 statement is stale. `crates/host/Cargo.toml` keeps rmcp/Tokio/notify outside the embedded core dependency surface. No runtime correctness defect or measured material size/latency cost was established from these duplicates. Forcing a core hash upgrade, replacing the accepted MCP SDK or changing macro dependencies solely to deduplicate is deferred dependency maintenance, requiring its own benefit and matching validation. |

The accepted compact query status DTO is owned by the query lane; this review does not duplicate its types or edit its version/schema logic. Provider/native fixes and their focused regressions are recorded separately in [the provider/native ledger](CODEBASE_REVIEW_0_0_2_PROVIDERS_NATIVE.md).

## Actual previous-native compatibility packet

The ignored operator packet is at `.artifacts/snow-leopard/previous-native-contract-01/`. It uses public final v0.0.1 Node/NuGet archives from `notarization-03/release`, independently pins the accepted release index's SHA256, and binds the actual newly built SDK/native/Smoke bytes to the new producer. No private historical build is required by the default suite.

Four mismatched cases—Node and .NET, new SDK9/old native8 and old SDK8/new native9—must return the public typed actionable `update_required` on a missing database, before admission creates the owned scope. Node additionally checks that user serialization did not run. Four matching controls must reach `not_ready`. The test-only managed `--contract-query` mode forces the exact FFI handle and exposes `KnowCodeException.Code`; this is fixture code, not a new SDK API. The same fixture uses only managed APIs shared by both SDKs; an actual assembly/API load incompatibility fails visibly and must not be relabeled as the expected query-contract refusal.

Root must execute the packet after a matching build containing the test-only mode, retain all raw commands/failures and record the exact new producer/source. Its README gives the command. Preparation and AST checking do **not** certify the matrix. It does not start a coordinator, restore dependencies, change HOME, assess Gatekeeper or claim universal compatibility with every historical native client.

## Review limits

Checks intentionally differ by operation; that alone is not a missing-capability bug. Existing fake-peer tests and the new actual archive matrix are finite evidence, not a proof over every capability permutation. No new concrete mismatch beyond the pending released8/current9 matrix was identified in this lane. If a missing field becomes necessary for an operation's actual safety contract, add its narrow comparison and mismatch regression at that boundary before considering a shared representation.
