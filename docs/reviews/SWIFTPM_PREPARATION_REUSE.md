# SwiftPM preparation reuse: source observations

Source-only checkpoint, 2026-11-13. The full Atelier run with an explicitly selected 4-GiB allowance is still running at this checkpoint. These observations establish neither a regression nor a speedup, and make no behavior change. Finish and qualify the actual corpus before selecting the next performance change.

1. **Avoid duplicate root-manifest evaluation within one analysis.** [`analyzePackage`](../../providers/swift/swiftpm.mjs#L105) evaluates the root manifest before dependency preparation, then the [dependency preflight](../../providers/swift/swiftpm.mjs#L111) evaluates every graph node, including the root ([`dependencyNodes`](../../providers/swift/swiftpm.mjs#L42)). Candidate: reuse that manifest only for the same canonical package, toolchain, SDK, configuration and environment, after proving its saved manifest/variant inputs did not change during preparation. This requires no persistent cache; its possible saving is one `dump-package` per root, not a measured large improvement.

2. **Measure duplicate dependency-cache work before sharing cache storage.** [`packageArguments`](../../providers/swift/swiftpm.mjs#L25) places both scratch and tool-managed cache under a [per-project/toolchain/configuration state directory](../../providers/swift/swiftpm.mjs#L97). Candidate: share only the public SwiftPM dependency cache if the selected tool's identity/invalidation and locking behavior qualifies. Preserve separate root build directories, checkouts, dependency plans and ordinary resolution. Existing [plan validation](../../providers/swift/swiftpm.mjs#L47) and [manifest/lock witnesses](../../providers/swift/swiftpm.mjs#L69) must remain effective. No module-output sharing follows from matching a package name or revision.

3. **Measure exact module-context duplication and warm incremental work.** Each root creates its own BSP/state; [owned-target preparation is sequential](../../providers/swift/swiftpm.mjs#L182) and can prepare a dependency closure. Before cross-root module reuse, record preparation time, effective toolchain/SDK/configuration, saved-input and artifact identities, and exact [compiler arguments/working-directory groups](../../providers/swift/swiftpm.mjs#L204). Existing settings groups describe semantic options; they are not by themselves a complete module-artifact compatibility proof. Keep incompatible contexts separate and let SwiftPM perform incremental preparation until reuse is established by compiler evidence.
