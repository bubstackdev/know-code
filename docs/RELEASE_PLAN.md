| Cross-repository queries | Resolve first-party package/project identities across registered workspaces; preserve reference-version and compilation-context evidence and bounded, coherent paths | Reuse identities, per-workspace SQLite stores, definition/dispatch evidence and common traversal operators. Do not load the full estate into memory or assume unrelated repository generations form one valid compilation. Snapshot selection and cross-repository path compatibility still need design. |
| Company onboarding | Given a company GitHub/GitLab root URL, enumerate repositories visible to the authenticated `gh`/`glab` scope; clone the whole visible corpus into hidden durable managed storage and keep clones/indexes up to date | Require the appropriate CLI installed and authenticated separately. Bound clone/fetch concurrency and bandwidth, reuse shared registry/scheduler/indexing/resource controls, and expose progress/failures. See [backlog details](COMPANY_ONBOARDING.md). |
| Angular templates | Compiler-backed template/component relationships, generated/mapped source provenance and explicit coverage/target boundaries | Narrow TypeScript/Angular adapter work feeding the same fact/update/query model; no separate graph engine. |
| Refactoring continuity | Evidence-bearing old/new identity links across moves/renames, fast enough to follow ordinary refactors | Use the saved-state update path; distinguish confirmed from possible continuity. Do not turn this into searchable source history or a code-editing product. |
| Estate operation | Hundreds of repositories on the local workstation with shared budgets, fair scheduling, bounded idle residency and upgrade/rebuild disk use | Build on the 0.0.1 operational foundation and measure representative C# service/Angular estates. Keep hardware requirements separate from the test machine's 64/128 GiB RAM. Do not silently assume server/distributed infrastructure. |

Before starting these workstreams, retain extension points in the common core and resist adding speculative abstractions. A release review should map every ledger row to implemented evidence or an explicit, user-approved scope decision. New research and experimental languages can remain in the repository without becoming advertised 0.0.1 capabilities.
