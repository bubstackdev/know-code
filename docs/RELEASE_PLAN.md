## What we can build on

The common Rust core already provides compilation-owned SQLite publication, saved-source retention, coherent read views, migration of compatible old formats, symbol/reference/source queries and bounded call/impact traversal. TypeScript/Roslyn extraction includes inferred TS, C# targets/configuration, locals, generated source and honest partial coverage. Compiler-selected project-body links and supported dispatch proofs retain compilation compatibility. Real Rust/.NET/Node parity and saved-file/restart/failure regressions exist.

The persistent coordinator already has a durable registry, sole-writer ownership, saved-file watching/reconciliation and stale fallback. NuGet/npm preparation is checkpointed rather than retried on every save. The live-state and accepted activity-notification work improves the common control path without changing storage/query ownership or requiring host background threads. These are implemented foundations, not evidence that every requirement below is done.

Other feedback items remain proposals; finish the selected shared query/projection gaps with matching .NET/Node contracts. Embedding completion remains in 0.0.1; this changes work order, not release scope.
3. Close operational safety: shared budgets/cancellation, bounded readers/cursors/WAL, recovery and replacement-index upgrades. Then finish settings and bounded parent discovery through the same registry/scheduler.
4. Finalize supported toolchains/dependency restoration and compiler/graph acceptance alongside those workflows; document supported coverage rather than chasing unrestricted runtime reconstruction.
5. Local runtime/npm/NuGet artifacts and the [user-scoped lifecycle](INSTALLATION.md) now pass outside-checkout and isolated launchd checks, including compatible update/rollback and data-preserving uninstall/reinstall. Add release automation and finish publication/clean-machine checks; verify zero telemetry and bundled SQLite identity on what will ship.
6. Run the final acceptance matrix, including real encoding when available, review the remaining ledger, then approve the concrete release artifacts/destinations before publishing.

Steps may overlap where their interfaces are independent. Avoid new performance experiments without an observed blocker or acceptance need; broad optimization is not an unbounded substitute for completing the product. No dates or release-readiness percentages are inferred from code volume or previous research.
