# Release gate: 0.5.1

The checks 0.5.1 shipped on, the same as [0.5.0's](0.5.0.md). None calls a model; each compares the release candidate
with 0.5.0. They measure what KnowCode returns and costs, not what agents do with it, so no claim about agents follows
from them.

**Builds.** 0.5.0 is the published release (macOS arm64 binary sha256 `47663315…ac771c0`). The 0.5.1 release candidate
is `release/0.5.1` at `bea2485` (main `5313dad` with the version change). Its Linux x86_64 binary (sha256
`d26c8eac…6fea2b62`) was built with the release's own packaging in a container. Its macOS arm64 binary (`fac6baaa…e060eb`)
was built with the same `dist` profile and path remapping, but not packaged by the release tooling: the macOS
acceptance run installed a hand-made archive of it with the Linux build's installer, which carries no macOS checksum.
The release itself is built by CI from the tagged commit; the shipped binaries come from that release workflow, so
the gates need only the same build profile, not its packaging.

## 0.5.0's misses

0.5.0 shipped with two misses, stated on its page. Both are met on 0.5.1.

- **Replay, strict scoring: met.** Under the scorer that reads only `path:line`, 0.5.0's two-hop impact recall fell to
  0.607, 0.001 past tolerance, because walked rows gave their call site as `at line N`. Rows now lead with their call
  site as `file:line`. Strict two-hop impact recall is 0.833 on 0.5.1, against 0.628 on 0.4.0 and 0.607 on 0.5.0.
  public2-two-hop-impact-009, the question 0.5.0 lost, scores 2 of 3 under either scorer.
- **History caller questions: met.** On 0.5.0, KnowCode had 1 of 2 against `git log -S`'s 2 of 2 at 2/3. Two things
  changed:
  - **The label:** history-callers-002's caller is marked `optional` in the public-v2 label it comes from
    (public2-two-hop-impact-009), and history-v1 dropped that flag. The corrected label carries it, and the gate scores
    an optional item as neither hit nor miss. Under it 0.5.0 itself has 1 of 1 at precision 1.0.
  - **The answer:** `history` now reaches that caller, a call through Serilog's `ILogger` in a class implementing it,
    and lists it (`ambiguous`) among the callers changed with the method.
  - Scored both ways on 0.5.1: corrected labels, 1 of 1 at precision 1.0 against `git log -S`'s 1 of 1 at 1/2; 0.5.0's
    original labels, 2 of 2 at precision 1.0 against 2 of 2 at 2/3.

## Workspace, installation and updates

- **Workspace gate** ([script](../../scripts/workspace-gate.py)), 111 pinned public repositories, macOS release
  candidate: every repository indexed and current by `knowcode serve` alone; a repository added later under the root
  noticed and indexed with nothing asked, and another indexed while asked about; 12 workspace answers checked, 6 of
  them while repositories were still waiting, none leaving a repository out without saying so.
- **Clean-machine acceptance** ([script](../../scripts/acceptance/clean-machine.sh)) on a fresh Linux x86_64 container
  (under emulation) and an isolated macOS home: the clean-machine checks, install from the release candidate's files,
  setup for Claude Code in three public repositories, the first-run runner's answers on each, uninstall and cleanup
  all passed on both. The client sessions were skipped: they call a model.
- **Update from 0.5.0, across the repository's new name,** in a fresh Linux container:
  - **0.5.0's installer:** the published installer downloaded under both names, `bubstackdev/knowcode` (redirected)
    and `bubstackdev/know-code`, is the same file, matching the release digest. Installed from the old name, its receipt
    names `knowcode`.
  - **0.5.0's self-update:** offered v0.5.1 under the new name by a stand-in for GitHub, it refuses ("installer URL
    is outside the expected KnowCode release"), as the changelog says.
  - **Re-running the installer**, the documented recovery, brings 0.5.1. The receipt then names `know-code`,
    configuration and notes come through unchanged, and the first query answers.
  - **The Claude Code plugin stays at 0.5.0** after the re-run until `knowcode setup claude` runs again, which moves it
    to 0.5.1.
  - **0.5.1's update checks** pass the test-owned checks with receipts naming either repository
    ([check-updates.py](../../scripts/check-updates.py)). Its self-update asks the new name's API and reports 0.5.1
    current.
  - The downloads came from the release candidate's files through the stand-in, not GitHub itself.
- **Binary scan** for private terms: nothing new.
