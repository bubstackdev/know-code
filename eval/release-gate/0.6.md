  - It passes with kc-small-fixes' capabilities fix (fix/caps-range 8202f83).
  - On the release candidate: TBD.
- **Restricted mode** passes on f112ff2. Under `serve --restricted` with one bound repository and `--ops find,refs`,

  - the scope is stated at `initialize`;

  - the server and its children hold no network socket, and the proxy sees no connection.

  f112ff2 changed no refusal code, and every refusal is coded.

## Worktrees

[worktree-gate.py](../../scripts/worktree-gate.py) (#167, on its head 2ffcf45) runs on three public repositories at
pinned commits: apple/swift-argument-parser, tokio-rs/axum and tokio-rs/tokio. Each has five worktrees on a shared
base: at the commit (two clean, one with uncommitted changes), 3 commits back (clean) and 15 back (with changes).
Each worktree's answers are compared with a separate index of it.

**Met. 0 mismatches and 0 failed checks on all 15 worktrees.**

- **Queries:** a fixed set of 16 to 18 per worktree, compared as JSON. Left out of the comparison are only the
  fields that name or measure one index: row ids, cursors, the generation, timings, a search's work counters, and
  "N seconds earlier" ages.
- **Freshness, in every worktree and both caches:**
  - a new untracked file is found;
  - a same-size edit with its modification time restored is seen with `KNOWCODE_VERIFY=1`;
  - a second one is seen without it, once a source read checks the file's hash.

  Each is done to a tracked file and to an untracked one.
- **Started at once:** four clean worktrees started at the same moment on a commit with no base. One built the base;
  the others waited and cloned it, with matching answers.

Instructions retired by `knowcode index --phases` (macOS, a loaded machine; instruction counts hold under load).
"Answerable" is what a query needs before it can answer; "derived" is the file ranking and the areas.

| Repository | Answerable, 5 worktrees (shared / separate) | With derived data | Disk after indexing (shared / separate) | 4 started at once (shared / separate) |
| --- | --- | --- | --- | --- |
| swift-argument-parser | 7.5G / 18.8G (0.40x) | 0.50x | 13.8 / 23.5 MB (0.59x) | 6.7G / 20.7G (0.32x) |
| axum | 8.8G / 21.9G (0.40x) | 0.49x | 13.6 / 25.7 MB (0.53x) | 8.9G / 22.9G (0.39x) |
| tokio | 20.5G / 71.6G (0.29x) | 0.49x | 31.5 / 77.3 MB (0.41x) | 27.0G / 95.0G (0.28x) |

- **Disk on APFS:** each file's own bytes (`ATTR_CMNEXT_PRIVATESIZE`), with a base's shared blocks counted once.
- **Disk on Linux with ext4:** the clone is a full copy, so worktrees on a shared base take more disk than separate
  indexes: 1.21x on swift-argument-parser (28.4 against 23.4 MB). Answers matched there too, in a Linux container,
  on all five worktrees and the at-once case.
- **Derived data is per worktree:** any change in a worktree recomputes the file ranking and areas over the whole
  repository (9.2G of 10.2G instructions for a 2-file change on tokio). A clean worktree at the base's commit carries
  the base's, and `status` says which.
