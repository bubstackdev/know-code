# Release gate: 0.6.0

The checks 0.6.0 shipped on are its [plan's gate](../../docs/plans/0.6.md#gate). None calls a model. Each compares the
release candidate with 0.5.1, the latest 0.5.x. They measure what KnowCode returns and costs, not what agents do with
it, so no claim about agents follows from them.

**Builds.** 0.5.1 is the published release (macOS arm64 binary sha256 `f2516065…c4f1dfe5`). The 0.6.0 release
candidate is `release/0.6.0` at `922466e` (integration/0.6 `f420ee1` with the version change), built with the release's
own packaging: macOS arm64 binary sha256 `fd4b2742…6d542d05`, Linux x86_64 (in a container) `2916457c…5e63a4f161`.
The release itself is built by CI from the tagged commit.

## Contract

The [contract gate](../../scripts/eval/contract_gate.py) checks what KnowCode says it offers against what its server
does, with made-up fixture repositories and loopback-only network watching.

- **Capabilities: pass (29 ops).** Each op's parameters, sample answers, ranges, choices, the single tool, writes and
  refusal codes match what the server accepts and returns.
- **Restricted mode: pass.** Under `serve --restricted` bound to one repository with an op allowlist, run with named
  tools and with the single `kc` tool: the scope is stated at startup, only allowed tools are listed, calls outside it
  are refused `not_allowed`, no file outside the cache changes, and no network socket is opened. It passed again in
  both clean-machine runs, on the installed binary (below).
- **Codes across the replay: pass.** The release candidate replayed twice gave the same answer or refusal, with the
  same codes, on all 686 calls; against 0.5.1, no call refused on both builds changed its code, and every refusal is
  coded.

## Worktrees

[worktree-gate.py](../../scripts/worktree-gate.py) on three public repositories at pinned commits
(apple/swift-argument-parser, tokio-rs/axum, tokio-rs/tokio), five worktrees each on a shared base: at the commit (two
clean, one with uncommitted changes), a few commits back (clean) and further back (with changes). Each worktree's
answers are compared with a separate index of it.

**Met: 0 mismatches and 0 failed checks on all 15 worktrees**, with the freshness cases (a new untracked file; same-size
edits with the modification time restored, to a tracked file and an untracked one) in every worktree and both caches.
Four clean worktrees started at once: one built the base, the others cloned it, with matching answers.

Instructions retired by the `index` commands (macOS, a loaded machine; instruction counts hold under load):

## Workspace, installation and updates

- **Workspace gate** ([script](../../scripts/workspace-gate.py)), 111 pinned public repositories, macOS release
  candidate: every repository indexed and current by `knowcode serve` alone; a repository added later under the root
  noticed and indexed with nothing asked, and another indexed while asked about; 14 workspace answers checked, 8 of
  them while repositories were still waiting, none leaving a repository out without saying so.
- **Clean-machine acceptance** ([script](../../scripts/acceptance/clean-machine.sh)) on a fresh Linux x86_64 container
  (under emulation) and an isolated macOS home, installing from the release candidate's files with its own installer:
  the clean-machine checks, install, setup for Claude Code in three public repositories, the first-run runner's answers,
  uninstall and cleanup passed on both. **Restricted mode** was checked on the installed binary before its removal
  (the contract gate's `restricted` check), and passed on both. The client sessions were skipped: they call a model.
  - **The first-run runner's 5-second bound on the first answer** failed for the eShop cases while the gates loaded the
    machine: on macOS eShopOnContainers (12.3 s), on Linux eShop (8.3 s) and eShopOnContainers (7.4 s), with every other
    check of theirs passing. Each was rerun once, alone: macOS eShopOnContainers passed (3.1 s), Linux eShop passed
    (3.2 s), Linux eShopOnContainers passed (1.8 s; its pinned commit fetched shallowly,
    since a full clone stalled under emulation).
- **Update from 0.5.1,** on Linux (container) and macOS (throwaway home): the published 0.5.1 installed, with
  configuration, a note, an index and the Claude Code plugin, updated itself to the release candidate through a stand-in
  for GitHub serving the candidate's files under `bubstackdev/know-code`. Configuration and notes came through
  unchanged, the plugin moved to 0.6.0, Claude Code's settings were unchanged, and the first query answered. The
  candidate's own update checks pass ([check-updates.py](../../scripts/check-updates.py)).
- **Binary scan** for private terms: one new open term, a 4-byte `strings` run in the Linux x86_64 binary's machine
  code. The user accepted it as noise.
