# Release gate: 0.5.0

The checks 0.5.0 shipped on ([plan](../../docs/plans/0.5.md#gate)). None calls a model; each compares the release
candidate with 0.4.0. They measure what KnowCode returns and costs, not what agents do with it, so no claim about agents
follows from them.

**Builds.** 0.4.0 is the published release (macOS arm64 binary sha256 `6ccc3b36…b865e801`). The 0.5.0 release
candidate was built from `release/0.5.0` at `f0adc5a` (integration/0.5 `c7d599a` with the version change): macOS arm64
binary sha256 `fe420060…62d072`, Linux x86_64 `28020bec…c489ef`. The release itself is built by CI from the tagged
commit.

**Errors:** none. Of the 15 `kc_search` calls that failed on 0.4.0, the 4 using look-around now answer, and the other 11
are refusals by design (their `paths` name files the public cohort doesn't have), counted in their own column.

**Not a clean pass.** Scored as the gate stood (the tables above, which read only `path:line`), two-hop impact recall
fell 0.021, missing the 0.02 tolerance by 0.001. It is one question, public2-two-hop-impact-009: 2 of 3 labelled places
to 1 of 3. 0.4.0 listed the call `serilog-aspnetcore/…/RequestLoggingMiddleware.cs:46` as a one-hop `cross-repo` row
with its own `path:line`. 0.5.0's walk across the library boundary lists the same call as a tree row,
`RequestLoggingMiddleware.init …/RequestLoggingMiddleware.cs:37 [ambiguous] direct at line 46`, with line 46 quoted
under it, so this scorer counts line 37, the constructor's declaration, and not the call.

From this gate on, the scorer also reads a row's call-site lines (`at line N (also M)`) as places in that row's file. That
counts the calls in every tree row, including in-repo rows (`… test at line 14`) that were always cited this way, so
it rescores 0.4.0 as well, and the absolute figures rise. Both builds, rescored:

| Question type | Recall | Precision |

## History questions

[history-v1](../history-v1/README.md)'s 14 questions on four public repositories at full history, labels from git
alone, scored with [history_gate.py](../../scripts/eval/history_gate.py) against the plain-git approaches an agent would
use.

Each part has its own verdict.

**Method-level questions (10): met.** KnowCode answers all 10 exactly, with nothing wrong listed; each plain approach
has lower recall, lower precision, or both.

| Method-level questions (10) | Recall | Precision |
| --- | ---: | ---: |
| KnowCode 0.5.0 (`history`) | 1.0 (73/73) | 1.0 (73/73) |
| `git log -L :name:FILE` | 0.526 (30/57) | 1.0 (30/30) |
| `git log -S name -- FILE` | 0.053 (3/57) | 0.333 (3/9) |
| `git log --follow -- FILE` | 0.965 (55/57) | 0.062 (55/885) |
| `git blame -L :name: FILE` | 0.375 (6/16) | 0.462 (6/13) |
| `git blame FILE` | 1.0 (16/16) | 0.018 (16/884) |

**Caller questions (2): not met.** KnowCode has recall 1 of 2 at precision 1 of 1, against `git log -S`'s 2 of 2 at
2 of 3: lower recall. It names history-callers-001's production caller (`Folder.cs`) and misses history-callers-002's,
`CachingReloadableLogger.cs`. That file calls `ForContext` on a field typed as Serilog's `ILogger`, a dependency's
interface, so the call resolves to `ILogger.ForContext` and not to `ReloadableLogger.ForContext`; `history`'s callers
come from `impact`'s first hop in the repo, which doesn't include it. The answer lists the file among those changed in
the same commits (2 of 2), but not as a caller. 0.5.0 ships with this miss; reaching such callers is 0.5.1 work.

| Caller questions (2) | Recall | Precision |
| --- | ---: | ---: |
| KnowCode 0.5.0 (`history`) | 0.5 (1/2) | 1.0 (1/1) |
| `git log -L :name:FILE` | 0 (0/2) | — |
| `git log -S name -- FILE` | 1.0 (2/2) | 0.667 (2/3) |
| `git log --follow -- FILE` | 1.0 (2/2) | 0.333 (2/6) |

**File co-change controls (2): met.** KnowCode (`coupled --since all`) lists 51 of 55 and 14 of 14 labelled files,
git's log 46 of 55 and 13 of 14 (with or without `--follow`). 0.4.0's `coupled` lists 33 of 55 and 14 of 14.

Pooled over the 12 method-level and caller questions, as `history_gate.py` reports them and passes them, KnowCode has
recall 0.987 (74/75) at precision 1.0; the pooled figure isn't the verdict. 0.4.0 has no `history`.

## Workspace, installation and updates

- **Workspace gate** ([script](../../scripts/workspace-gate.py)), 111 pinned public repositories, macOS release
  candidate: every repository indexed and current by `knowcode serve` alone, with no `index` command; a repository added
  later under the root noticed and indexed with nothing asked, and another indexed while asked about; 12 workspace
  answers checked, 7 of them while repositories were still waiting, none leaving a repository out without saying so.
  The times it prints are wall-clock on a loaded machine and indicative only.
- **Clean-machine acceptance** ([script](../../scripts/acceptance/clean-machine.sh)) on a fresh Linux x86_64 container
  (under emulation) and an isolated macOS home: the clean-machine checks, install from the release candidate's files,
  setup for Claude Code in three public repositories, the first-run runner's answers on each, uninstall and cleanup
  all passed on both. The client sessions were skipped: they call a model.
- **Update from 0.4.0:** the published 0.4.0 installed in an isolated home updated itself to the release candidate;
  configuration and notes came through unchanged, and the Claude Code plugin moved to 0.5.0, keeping the default `one`
  profile. The downloads came from the release candidate's files through a stand-in for GitHub, not GitHub itself.
  A refused GitHub API still falls back to the release page and holds off the API until the reset.
- **Binary scan** for private terms: nothing new.
