# Release gate: 0.5.0

The checks 0.5.0 shipped on ([plan](../../docs/plans/0.5.md#gate)). None calls a model; each compares the release
candidate with 0.4.0. They measure what KnowCode returns and costs, not what agents do with it, so no claim about agents
follows from them.

**Builds.** 0.4.0 is the published release (macOS arm64 binary sha256 `6ccc3b36…b865e801`). The 0.5.0 release
candidate was built from `release/0.5.0` at `f0adc5a` (integration/0.5 `c7d599a` with the version change): macOS arm64
binary sha256 `fe420060…62d072`, Linux x86_64 `28020bec…c489ef`. The release itself is built by CI from the tagged
commit.

**Errors:** none. Of the 15 `kc_search` calls that failed on 0.4.0, the 4 using look-around now answer, and the other 11
are refusals by design (their `paths` name files the public cohort doesn't have), counted in their own column.

**Two-hop impact recall fell 0.021, past the gate's 0.02 tolerance.** It is one question, public2-two-hop-impact-009,
2 of 3 labelled places to 1 of 3. 0.4.0 listed the call
`serilog-aspnetcore/…/RequestLoggingMiddleware.cs:46` in its one-hop `cross_repo` rows. 0.5.0's walk across the library
boundary lists the same call as a tree row, `RequestLoggingMiddleware.init …/RequestLoggingMiddleware.cs:37 [ambiguous]
direct at line 46`, with line 46 quoted under it. The gate reads only `path:line`, so it scores line 37, the
constructor's declaration. Scored again with each row's call-site lines (`at line N`, `also M`) read as well, on both
builds, two-hop impact recall is 0.826 → 0.826 and precision 0.328 → 0.320, within tolerance, and every other type is
unchanged.

## History questions

[history-v1](../history-v1/README.md)'s 14 questions on four public repositories at full history, labels from git
alone, scored with [history_gate.py](../../scripts/eval/history_gate.py) against the plain-git approaches an agent would
use.

| Method-level and caller questions (12) | Recall | Precision |
| --- | ---: | ---: |
| KnowCode 0.5.0 (`history`) | 0.987 (74/75) | 1.0 (74/74) |
| `git log -L :name:FILE` | 0.508 (30/59) | 1.0 (30/30) |
| `git log -S name -- FILE` | 0.085 (5/59) | 0.417 (5/12) |
| `git log --follow -- FILE` | 0.966 (57/59) | 0.064 (57/891) |
| `git blame -L :name: FILE` | 0.375 (6/16) | 0.462 (6/13) |
| `git blame FILE` | 1.0 (16/16) | 0.018 (16/884) |

KnowCode answers the 10 method-level questions exactly. Of the two caller questions it names the one production caller
of history-callers-001 and misses the one of history-callers-002, a call through Serilog's `ILogger` inside
Serilog.Extensions.Hosting that `impact` doesn't reach; `git log -S` finds both callers' commits, with one wrong
commit. On the two file co-change controls KnowCode (`coupled --since all`) lists 51 of 55 and 14 of 14 labelled
files, git's log 46 of 55 and 13 of 14. 0.4.0 has no `history`; its `coupled` lists 33 of 55 and 14 of 14.

## Workspace, installation and updates

- **Workspace gate** ([script](../../scripts/workspace-gate.py)), 111 pinned public repositories, macOS release
  candidate: every repository indexed and current by `knowcode serve` alone, with no `index` command; a repository added
  later under the root noticed and indexed with nothing asked, and another indexed while asked about; 12 workspace
  answers checked, 7 of them while repositories were still waiting, none leaving a repository out without saying so.
  The times it prints are wall-clock on a loaded machine and indicative only.
- **Clean-machine acceptance** ([script](../../scripts/acceptance/clean-machine.sh)) on a fresh Linux x86_64 container
  (under emulation) and an isolated macOS home: the clean-machine checks, install from the release candidate's files,
  setup for Claude Code in three public repositories, the first-run runner's answers on each, uninstall and cleanup
  all passed on both. The client sessions were skipped: they call a model.
- **Update from 0.4.0:** the published 0.4.0 installed in an isolated home updated itself to the release candidate;
  configuration and notes came through unchanged, and the Claude Code plugin moved to 0.5.0, keeping the default `one`
  profile. The downloads came from the release candidate's files through a stand-in for GitHub, not GitHub itself.
  A refused GitHub API still falls back to the release page and holds off the API until the reset.
- **Binary scan** for private terms: nothing new.
