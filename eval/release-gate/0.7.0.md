# Release gate: 0.7.0

0.7 is compared with **0.6.1**, the published release. The checks are those of the [0.7 plan's
gate](../../docs/plans/0.7.md#gate). None calls a model. They measure what KnowCode returns and costs, not what agents
do with it, so no claim about agents follows from them.

**Builds.** 0.6.1 is the published release: its macOS arm64 archive matches the digest GitHub publishes for it
(`b5420f43…`), and its Linux files were used as published. The 0.7.0 release candidate is integration/0.7 at **43ac792**
with the version changed to 0.7.0 (a local commit, `68fd62d`, as 0.6.1's `release/0.6.1` was), built with the release's
own packaging (`scripts/package-native.sh`, cargo-dist 0.33.0): macOS arm64 archive sha256 `6de539de…` (binary
`78ea5e8e…`), and Linux **aarch64** in a throwaway `rust:1.98.0-bookworm` container (binary `0851e8b1…`). Measurements
that need no packaged release used a plain release build of 43ac792 (`c6f7c316…`). Every run used a fresh cache, config
and data directory of its own. The release itself is built by CI from the tagged commit.

**Linux here is aarch64, not x86_64.** 0.6.1's gate ran Linux x86_64 under emulation; this gate ran Linux aarch64
natively, by the maintainer's decision. The x86_64 release files are still checked by the release workflow's
linux-compat job (`scripts/check-glibc.py` and `scripts/check-linux-compat.sh`).
