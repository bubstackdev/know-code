# Release gate: 0.7.0

0.7 is compared with **0.6.1**, the published release. The checks are those of the [0.7 plan's
gate](../../docs/plans/0.7.md#gate). None calls a model. They measure what KnowCode returns and costs, not what agents
do with it, so no claim about agents follows from them.

**Status of this page.** The release candidate isn't cut yet. The figures below are each workstream's published
measurement on `integration/0.7`, named with its pull request or file and the build it ran on; every one is a public
repository's. Items marked **not yet run** are run on the release candidate, as 0.6.1's were, and this page is
completed with their results and the candidate's build digests before the release. A figure measured here and again on
the candidate is replaced by the candidate's, and any difference is explained.

## Identity, C#, Swift and TypeScript

The [identity gate](../../scripts/eval/identity_gate.py) on [identity-v1](../identity-v1): the same 4,943 labels as
0.6.1's, each repository indexed alone.

| Language | `exact` precision | Recall, linked, 0.6.1 → 0.7 | Outside labels linked, 0.6.1 → 0.7 | Last measured |
| --- | ---: | ---: | ---: | --- |
| C# | 0.998 (879/881) | 0.728 → 0.776 (997/1,285) | 6 → **0** | #346, integration/0.7 at 4425a9e plus the change |
| Swift | 0.998 | 0.575 → 0.579 | 22 → **0** | #243, unchanged by #275 |
| TypeScript | 0.998 | 0.579 → 0.597 | 37 → **2** | #249, unchanged by #264 and #266 |

- **`exact` precision of at least 0.99: met in all three.** Against 0.6.1 no label is newly wrong: each of W6's
  changes (#227, #235, #243, #249) was checked with `identity_gate.py compare` against its base, and none made a label
  wrong. The list of every wrong `exact` link (0.6.1 had ten) is taken on the candidate: **not yet run**.
- **Linked recall** rose in all three; no drop.
- **No outside label linked: met in C# and Swift. TypeScript has 2**, both in jellyfin-web, from one cause. Both are a
  member read on react-query's `data` (`data?.TotalRecordCount` at
  `src/apps/dashboard/routes/activity/index.tsx:123`, `filtersLegacy?.OfficialRatings` at
  `src/apps/modern/features/libraries/components/filter/FilterButton.tsx:354`). Their type is react-query's `TData`,
  inferred from the hook's `queryFn`, which KnowCode doesn't infer, so the member falls to the name rules and links
  to the repo's one same-named declaration as `unique_name`. The toolchain binds both to `@jellyfin/sdk` models. Neither
  is `exact`. The cheap fix (treat everything a `useQuery` hook returns as the package's) would unlink correct links in
  the same repo, where fetchers cast to the repo's own models. **The maintainer decided 0.7 ships with these two
  listed; the fix, TData inference, is in 0.8.**

## Routes

Labels come from each framework's own route listing, run in a throwaway container; precision of at least 0.95 per
framework, recall reported.

### Spring (Java and Kotlin)

[routes-v1](../routes-v1/README.md) "Java and Kotlin (Spring)": 119 labels from Spring's own `RequestMappingHandlerMapping`
(two identical labelling passes, frozen at 222867e), scored on #343 at 8814a9c (#350):

- **Precision 1.000 (82/82, Wilson 0.955–1.000); recall 0.698 (83/119, 0.610–0.773).** Every repository is 1.000/1.000
  except spring-petclinic-rest (1/37): its controllers implement interfaces that openapi-generator writes at build time,
  which KnowCode doesn't read.
- **Pass on precision.** The plan's gate is precision; routes-v1's README asks for precision and recall. The
  maintainer ruled that Spring passes under the plan's gate; the README's rule is unchanged and the disagreement is
  stated in #350's results.
