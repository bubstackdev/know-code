# Release gate: 0.4.0

The checks 0.4.0 shipped on ([plan](../../docs/plans/0.4.md#gate)). None calls a model; each compares the release
candidate with 0.3.0. They measure what KnowCode returns and costs, not what agents do with it, so no claim about agents
follows from them.

**Builds.** 0.3.0 is the published release (macOS arm64 binary sha256 `b7ab63ba…991228`). The 0.4.0 release candidate
was built from `release/0.4.0` at `8cabc48` (main `5762f3e` with the version change): macOS arm64 binary sha256
`a365b07a…67cf9a`, Linux x86_64 `c437c999…f381`. The release itself is built by CI from the tagged commit.

## Workspace, installation and updates

- **Workspace gate** ([script](../../scripts/workspace-gate.py)), 111 pinned public repositories, macOS release
  candidate: every repository indexed and current by `knowcode serve` alone, with no `index` command; a repository added
  later under the root noticed and indexed with nothing asked, and another indexed while asked about; 16 workspace
  answers checked, 10 of them while repositories were still waiting, none leaving a repository out without saying so.
  The times it prints are wall-clock on a loaded machine and indicative only.
- **Clean-machine acceptance** ([script](../../scripts/acceptance/clean-machine.sh)) on a fresh Linux x86_64 container
  and an isolated macOS account: install, setup for Claude Code, the first answer on three public repositories through
  the default `kc` tool, uninstall and cleanup all passed on both.
- **Update from 0.3.0:** the published 0.3.0 installed in an isolated home updated itself to the release candidate;
  configuration and notes came through unchanged, and the Claude Code plugin moved from 0.3.0's `all` profile to the
  new default. The downloads came from the release candidate's files through a stand-in for GitHub, not GitHub itself.
  On the release candidate, a refused GitHub API falls back to the release page and holds off the API until the reset.
- **Binary scan** for private terms: nothing new.
