# Release gate: 0.6.1

0.6.0 was tagged but never published, so 0.6.1 is compared with **0.5.1**, the published release. Where the
[0.6.0 gate](0.6.0.md) measured the same thing on its release candidate, the figure is given too, to show that 0.6.1
doesn't fall back from it. The checks are those of the [0.6 plan's gate](../../docs/plans/0.6.md#gate), run the way
0.6.0's were. None calls a model. They measure what KnowCode returns and costs, not what agents do with it, so no claim
about agents follows from them.

**Builds.** 0.5.1 is the published release (macOS arm64 binary sha256 `f2516065…c4f1dfe5`; each of its files used here
matches the digest GitHub publishes for it). The 0.6.0 release candidate is the one 0.6.0's gate measured
(`fd4b2742…6d542d05`). The 0.6.1 release candidate is `release/0.6.1` at `db8e394` (integration/0.6 `cd50332` with the
version change), built with the release's own packaging: macOS arm64 binary sha256 `346b375a…69f47e3d`, Linux x86_64 (in
a container) `2515b271…797852e1`. Both builds passed the build-path, first-run, workspace first-run and installer
checks. The release itself is built by CI from the tagged commit.

The 0.5.1 and 0.6.0 figures are the 0.6.0 gate run's own results. The gate scripts are unchanged since then, and so is
the 0.5.1 binary. Every run of the 0.6.1 candidate used a fresh cache of its own.

## Contract

The [contract gate](../../scripts/eval/contract_gate.py) checks what KnowCode says it offers against what its server
does, with made-up fixture repositories and loopback-only network watching.

- **Capabilities: pass (29 ops).** Each op's parameters, sample answers, ranges, choices, the single tool, writes and
  refusal codes match what the server accepts and returns.
- **Restricted mode: pass.** Under `serve --restricted` bound to one repository with an op allowlist, run with named
  tools and with the single `kc` tool: the scope is stated at startup, only allowed tools are listed, calls outside it
  are refused `not_allowed`, no file outside the cache changes, and no network socket is opened. It passed again in
  both clean-machine runs, on the installed binary (below).
- **Codes across the replay: pass.** The release candidate replayed twice gave the same answer or refusal, with the
  same codes, on all 686 calls; against 0.5.1, no call refused on both builds changed its code, and every refusal is
  coded.

## Workspace, installation and updates

- **Workspace gate** ([script](../../scripts/workspace-gate.py)), 111 pinned public repositories, macOS release
  candidate: every repository indexed and current by `knowcode serve` alone; a repository added later under the root
  noticed and indexed with nothing asked, and another indexed while asked about; 14 workspace answers checked, 7 of
  them while repositories were still waiting, none leaving a repository out without saying so.
- **Clean-machine acceptance** ([script](../../scripts/acceptance/clean-machine.sh)) on a fresh Linux x86_64 container
  (under emulation) and an isolated macOS home, installing from the release candidate's files with its own installer:
  the clean-machine checks, install, setup for Claude Code in three public repositories, the first-run runner's answers
  (each within its 5-second bound on the first answer), uninstall and cleanup passed on both, with no step rerun.
  **Restricted mode** was checked on the installed binary before its removal (the contract gate's `restricted` check),
  and passed on both. The client sessions were skipped: they call a model.
- **Update from 0.5.1,** on Linux (a container with no network) and macOS (a throwaway home): the published 0.5.1,
  installed by its own installer, with configuration, a note, an index and the Claude Code plugin, updated itself to
  the release candidate with `knowcode self-update`, through a stand-in for GitHub serving the 0.5.1 and candidate files
  under `bubstackdev/know-code`. No other address was asked for. Configuration and notes came through unchanged, the
  plugin moved to 0.6.1, Claude Code's settings were unchanged, and the first query answered, with the note still on its
  symbol. The candidate's own update checks pass ([check-updates.py](../../scripts/check-updates.py)).
- **Binary scan** for private terms, over both platforms' release files with each binary's strings: 11 open ids, every
  one already open in 0.6.0's scan and earlier releases'; none is new. One id open in 0.6.0 no longer appears.
