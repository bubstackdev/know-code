# Working with the user

- Use Q&A for architecture and product discussions: ask one focused question at a time, then build on the answer.
- Keep conversational responses short. Do not leave a large block of analysis for the user to read and respond to.
- Put detailed reasoning and research in durable repository documentation, and summarize changes briefly.
- Keep work, reference clones, and artifacts in durable project locations. Do not use `/tmp`, `/private/tmp`, or other reboot-cleaned locations for work that will be retained or referenced. Put local reference clones under `.research/repos/` and keep findings in `docs/`.
- Continue authorized, reversible work without repeatedly asking permission. Questions should resolve actual product or architecture decisions.

- Read [docs/PRODUCT_CONSTRAINTS.md](docs/PRODUCT_CONSTRAINTS.md) before changing product behavior. It preserves the complete accepted requirements formerly embedded here. [docs/DESIGN.md](docs/DESIGN.md) is the design reference; proposals and performance goals are not implemented guarantees.
- Read [docs/IMPLEMENTATION.md](docs/IMPLEMENTATION.md) before extending code, then the relevant feature document. Verify current code and constants; [docs/AGENT_HISTORY.md](docs/AGENT_HISTORY.md) contains historical checkpoints, not current status.

The user explicitly deferred the real video-encoding performance gate; do not claim it passed.
- v0.0.2 is stabilization only: correctness, performance, reliability and simplification. New features previously assigned to 0.0.2 move to later releases with timing undecided. Track review dispositions and actual evidence in [docs/CODEBASE_REVIEW_0_0_2.md](docs/CODEBASE_REVIEW_0_0_2.md); retain the original CODEBASE-REVIEW.md unchanged.
- Use one Rust core for storage, queries and graph traversal, with thin in-process .NET/Node bindings and CLI/MCP host layers. Keep compiler semantics in narrow language adapters using the shared bounded Protobuf protocol. Avoid a new engine, framework or validation layer per responsibility.
- Published builds must have zero usage telemetry, including local collectors and hidden opt-ins. Debug/personal diagnostic collection is local-only and bounded; see [docs/DIAGNOSTICS.md](docs/DIAGNOSTICS.md). License is Apache-2.0; reference clones retain upstream licenses.
- Preserve compiler-backed identity/evidence, exact saved-source UTF-8 coordinates and compilation/target compatibility. Report stale, partial, unavailable and unresolved states honestly. Never infer body/dispatch links from names or opaque ID structure. See [docs/FACT_MODEL.md](docs/FACT_MODEL.md) and [docs/CALL_GRAPH.md](docs/CALL_GRAPH.md).
- Coordinator is the sole index writer. Publish coherently, preserve reader generations and explicit snapshot/cursor invalidation, bound retention, and retain failed cleanup charges. Keep indexes/settings outside repositories in durable per-user storage. See [docs/COORDINATOR.md](docs/COORDINATOR.md), [docs/CURSOR_INTEGRATION.md](docs/CURSOR_INTEGRATION.md), [docs/WAL_PRESSURE.md](docs/WAL_PRESSURE.md) and [docs/INDEX_RECOVERY.md](docs/INDEX_RECOVERY.md).
- Every repository requires a separate personal trust grant before compiler/dependency execution. Opening/registering is not consent. Package lifecycle scripts/hooks require their own default-off personal grant. Checked-in settings cannot grant either permission. See [docs/WORKSPACE_SETTINGS.md](docs/WORKSPACE_SETTINGS.md).
- Honor repository-selected compiler/SDK/package tools; Node/.NET prerequisites are user-installed. Restore dependencies through the common preparation/invalidation path, not on every save. Preserve linked sources with honest origin evidence. See provider documentation and [docs/CSHARP_CONTEXTS.md](docs/CSHARP_CONTEXTS.md).
- Current supported distribution is macOS 15+ Apple Silicon, Node 24 and a separately installed .NET 10 SDK. TS/C# are supported; Swift/Rust source adapters remain experimental. All declared C# targets share one selected build context; never silently skip targets or combine incompatible graph paths.
- Resource efficiency is a priority. Automatic shared defaults are two CPU cores/2 GiB, not hardware requirements. Keep request/admission/transport/disk budgets shared and bounded, preserve typed errors and host cancellation conventions, and keep background indexing independent from consumer lifetime. See [docs/RESOURCE_CONTROL.md](docs/RESOURCE_CONTROL.md), [docs/QUERY_ADMISSION.md](docs/QUERY_ADMISSION.md) and [docs/QUERY_LIFECYCLE.md](docs/QUERY_LIFECYCLE.md).
- Saved on-disk files are the permanent freshness boundary. Unsaved editor buffers are out of scope. Retained generations are coherent reader/recovery state, not searchable history.
- Do not replace the live development LaunchAgent, alter original test repositories, or publish a new release merely to validate a change. Use isolated owned data/prefixes and durable snapshots; see [docs/LOCAL_INSTALL.md](docs/LOCAL_INSTALL.md).

# Development and validation

- Build matching artifacts with `bash scripts/build.sh [debug|release]`. Toolchains are user-scoped; preserve real HOME/CODEX_HOME. Use the supported sandbox escalation mechanism when local Unix sockets/FSEvents or other required OS operations are blocked.
- During iteration use `bash scripts/test.sh` for quick source checks or select explicit IDs (`--list`). A release checkpoint uses matching artifacts plus `bash scripts/test.sh release core` and relevant extended checks from [docs/VALIDATION.md](docs/VALIDATION.md). `bash scripts/test.sh release all` preserves complete historical coverage. The new default is quick, not the old full suite; do not relabel old/partial receipts. Repeat broad checks only when changes/failures justify them.
- Formatting/checks: `cargo fmt --all -- --check` and `cargo clippy --workspace --all-targets --locked -- -D warnings`. Coordinate one heavy build/test owner when agents work in parallel; do not multiply full suites or mutate the same producer outputs concurrently.
- Keep tests/artifacts under `.artifacts`, reference clones under `.research/repos`, and findings in `docs`. Never retain work in reboot-cleaned `/tmp` or `/private` locations. Preserve failed attempts; a passing suffix or isolated rerun does not turn a failed full run into success.
- Keep source/build/profile/package/signing evidence bound to the actual artifact. Reuse existing packaging/provenance mechanisms; do not certify stale binaries with new source hashes. [docs/PACKAGING.md](docs/PACKAGING.md) and [docs/reviews/NOTARIZATION_OPERATOR.md](docs/reviews/NOTARIZATION_OPERATOR.md) describe distribution verification.
